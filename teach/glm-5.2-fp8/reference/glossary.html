术语表：GLM-5.2 架构与 SGLang DSA 实现

本 workspace 的规范命名。所有课件、记录沿用这里的术语与首选词。GLM-5.2 = MLA + DSA + IndexShare 的超长上下文 MoE 模型。

算法 / 架构

DSA（Dynamic Sparse Attention）

单层内的稀疏注意力：用轻量 indexer 为每个 query 选出 top-index_topk（GLM-5.2=2048）个最相关 key，只对它们做 attention。压缩"对哪些 token 算"。

避免：sparse attention（太泛）、NSA（那是另一种 indexer 设计）

IndexShare

GLM-5.2 的算法增量：DSA 的 index 不再每层重算，而是每 index_topk_freq（=4）层算一次、中间层复用。压缩"多久重选一次 token"，与 DSA 正交。1M context 下省 2.9× attention FLOPs。论文 arXiv:2603.12201 IndexCache。

避免：index reuse（口语化）、cross-layer attention（那是共享 attention 输出，不是 index）

MLA（Multi-head Latent Attention）

DeepSeek 风格的注意力：KV 经 low-rank 投影压成 latent（GLM-5.2 kv_lora_rank=512）存进 cache，省显存。GLM-5.2 的 attention 主路径。

Indexer（lightning indexer）

DSA 里选 top-k 的轻量模块：MQA 结构（index_n_heads=32 × index_head_dim=128，单头 key），q 来自 q_lora，经 k_norm + RoPE + weights_proj，用 FP8 deep_gemm 算 MQA logits 再 topk。便宜地为每 query 打分所有 key。

MTP（Multi-Token Prediction）

单 nextn draft 层（GLM-5.2 layer 78），用于 speculative decoding。GLM-5.2 acceptance length +20%。上游 SGLang 把它改名复用 DeepSeek 的 DeepseekV3ForCausalLMNextN。

first_k_dense_replace

前 K 层用 dense FFN 而非 MoE（GLM-5.2=3，即 layer 0–2 dense）。保浅层 representation 质量。

SGLang 实现

能力探测（capability-driven）

框架靠 config 字段（如 index_topk is not None）而非架构名身份决定走哪条路径。GLM-5.2 day-0 能"零新文件"的根因。对立面是身份驱动（identity-driven）的 if arch=="GLM"。

is_deepseek_dsa()

上游的能力探测函数（model_config.py:103）：架构名进白名单 set 且有 index_topk → 打开 use_dsa + Indexer + dsa 后端。GLM 的"接入"=往这个 set 加一个字符串。

skip_topk / next_skip_topk

每层在 __init__ 算好的布尔（deepseek_v2.py:1604）。skip_topk=本层不跑 indexer、复用上层 index；next_skip_topk=本层 index 要传给下层。IndexShare 的层级开关。

prev_topk_indices

IndexShare 层间传递的载体：层循环的局部变量 topk_indices，作为参数一层层下传（deepseek_v2.py:2495）。不是全局 cache，生命周期=一次 forward。

避免：index cache（上游没有缓存对象）

dsa 后端

DSA 的 attention backend（DeepseekSparseAttnBackend）。is_deepseek_dsa 为真时 server_args 自动选。nsa 是其已废弃别名（直接转发）。

避免：nsa backend（已弃用名）

EntryClass

SGLang 模型注册约定：模块导出 EntryClass=[...]，ModelRegistry 扫描登记，用 architectures[0] 字符串查表。GLM 挂在 glm4_moe.py:1486。

index_share_for_mtp_iteration

第二条复用通道（时间维度）：speculative draft 各 step 间复用 base 的 index，载体是 forward_batch.topk_indices 字段。仅 topk==1（否则 tree 重排 desync）。
