Lesson 01 · MiniMax M3 Architecture

MiniMax M3: 整体架构与计算流程

MiniMax M3 是一个 ~428B 总参数、~23B 激活参数的原生多模态 MoE 模型，支持 1M token context。本课聚焦其 text backbone 的算法架构。

4. Attention 算法详解

4.1 基础 GQA 结构

所有 60 层共享相同的 attention 投影结构：

graph TD H["hidden (B, L, 6144)"] --> QP["Q Proj → (B, L, 64, 128)"] H --> KP["K Proj → (B, L, 4, 128)"] H --> VP["V Proj → (B, L, 4, 128)"] QP --> QN["Q Norm (per-head RMS)"] KP --> KN["K Norm (per-head RMS)"] QN --> ROPE["Partial RoPE
仅 dim[:64] 旋转"] KN --> ROPE ROPE --> ATT{"Layer 0-2: Full Attention
Layer 3-59: MSA Sparse"} VP --> ATT ATT --> OP["O Proj → (B, L, 6144)"]
Partial RoPE：head_dim=128 中仅前 64 维施加旋转位置编码，后 64 维不编码位置。这种设计让模型同时拥有位置敏感特征和位置无关特征，有助于长 context 泛化。
[config.json: partial_rotary_factor=0.5, rotary_dim=64]

4.2 MiniMax Sparse Attention (MSA) — 核心创新

MSA 的核心思想：在 GQA 基础上，为每个 KV group 独立选择 top-k 个 KV block 做精确注意力，跳过不重要的 block。

graph TD subgraph "Index Branch (轻量级, 独立权重)" IQ["Index Q Proj
hidden → (4 heads, 128 dim)"] IK["Index K Proj
hidden → (1, 128 dim)"] IQ --> IQN[Index Q Norm] IK --> IKN[Index K Norm] IQN --> ROPE2["RoPE + Hadamard"] IKN --> ROPE2 ROPE2 --> SCORE["Block Score:
per-block max(Q·K) over tokens"] SCORE --> TOPK["Top-k Selection
k=16 blocks per group"] end subgraph "Main Branch (原始 GQA)" Q["Q (64 heads)"] --> SPARSE_ATT K["K (4 heads)"] --> SPARSE_ATT V["V (4 heads)"] --> SPARSE_ATT TOPK --> |"selected block indices"| SPARSE_ATT["Block-Sparse Attention
仅对选中的 16 blocks 计算"] end SPARSE_ATT --> OUT["Attention Output"]
MSA 算法步骤：
  1. Index Branch 计算 block scores：用独立的小 Q/K 投影（4 heads × 128 dim）计算每个 KV block 的重要性分数。Score 取 block 内所有 token 的 Q·K 点积的 max。
  2. Top-k 选择：每个 GQA group 独立选 top-16 个 block（block_size=128 tokens）。加上 1 个 local block（当前位置附近）。
  3. Main Branch 稀疏注意力：原始的 64 头 Q 仅对选中的 16+1 个 block（共 ~2176 tokens）做精确 softmax attention，跳过其余 block。

在 1M context 下，每个 token 只需关注 ~2176/1M ≈ 0.2% 的 KV，compute 降低约 28.4×。

[arXiv:2606.13392, sparse_topk_blocks=16, sparse_block_size=128, sparse_local_block=1]

从权重结构可以验证 Index Branch 的存在：

self_attn.index_q_proj.weight   # (512, 6144) = 4 heads × 128 dim ← hidden
self_attn.index_k_proj.weight   # (128, 6144) = 1 head × 128 dim ← hidden

注意：Index K 只有 1 个 head（所有 4 个 Index Q heads 共享同一个 K），这进一步降低了 Index Branch 的计算量。

5. MoE Block 算法

graph TD X["input (B, L, 6144)"] --> GATE["Gate Proj → (B, L, 128)
dtype=float32"] GATE --> SIG["Sigmoid Scoring
(not softmax)"] SIG --> BIAS["+ e_score_correction_bias"] BIAS --> TOP4["Top-4 Selection"] TOP4 --> |"expert ids + weights"| ROUTE X --> ROUTE["Routed Dispatch"] ROUTE --> EXP["4 Selected Experts
each: SwiGLU(6144→3072→6144)"] EXP --> |"weighted sum"| MERGE X --> SHARED["Shared Expert
SwiGLU(6144→3072→6144)"] SHARED --> MERGE["Sum"] MERGE --> OUT["output (B, L, 6144)"]
MoE 设计要点：
  • Sigmoid scoring（非 softmax）：gate logits 过 sigmoid 而非 softmax，每个 expert 的得分独立，不互相抑制。这允许多个 expert 同时获得高分。[config: scoring_func=sigmoid]
  • Bias correction：每个 expert 有一个可学习 bias（e_score_correction_bias），调节 expert 的被选概率，平衡 load。[config: use_routing_bias=true]
  • Routed scaling factor = 2.0：routed experts 的输出乘以 2.0，补偿稀疏激活带来的幅度缩减。[config: routed_scaling_factor=2.0]
  • Shared expert always on：1 个共享 expert 处理所有 token，确保基线表达能力。

6. 激活函数: SwiGLU with Clamp

M3 使用 swigluoai 变体：

SwiGLU(x) = SiLU(x·W_gate) ⊙ (x·W_up)
# 但加了 clamp:
output = clamp(SwiGLU(x), -swiglu_limit, +swiglu_limit)
# swiglu_limit = 7.0, swiglu_alpha = 1.702

Clamp 防止极端激活值在深层累积，稳定训练。alpha=1.702 是 SiLU 的缩放系数（GELU 近似中常见）。

7. MTP (Multi-Token Prediction)

Config 中声明 num_mtp_modules=7, num_nextn_predict_layers=1，但发布的权重中不含 MTP 模块参数。这意味着：

  • MTP 仅用于训练阶段的辅助 loss（预测未来 7 个 token）
  • 推理时不加载 MTP head，仅用标准 autoregressive decoding
  • 或者 MTP 被用于 speculative decoding 的 draft model，但作为独立部署
