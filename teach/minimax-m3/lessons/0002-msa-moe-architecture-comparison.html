Part A: MSA 数学推导与近似误差分析

A.1 从 Full Attention 到 Block-Sparse Attention 的形式化

标准 causal attention 对位置 t、head h：

o_t^(h) = Σ_{i≤t} α_{t,i}^(h) · v_i^(h)

α_{t,i}^(h) = exp(q_t^(h) · k_i^(h) / √d_h) / Σ_{j≤t} exp(q_t^(h) · k_j^(h) / √d_h)

计算量：Θ(2·H_q·N²·d_h) FLOPs，N=1M 时不可接受。

Block-Sparse 的核心思想：将 KV sequence 分割为 B = ⌈N/B_k⌉ 个 block，每个 block 包含 B_k 个连续 token。对每个 query 只选 k 个 block 做 attention：

Block partition:  𝔹_b = {(b-1)·B_k + 1, ..., min(b·B_k, N)},  b = 1,...,B

Selected blocks:  I_i^(r) ⊆ {1,...,B},  |I_i^(r)| = k

Sparse output:    O_i^(h) = softmax(Q_i^(h) · K[I_i^(r)]^T / √d_h) · V[I_i^(r)]

其中 r 是 GQA group index（h ∈ H_r），同一 group 的所有 query heads 共享同一组 selected blocks。

Block-level 而非 token-level 选择的原因：
  1. GPU 计算友好：Token-level 的 scatter/gather 无法充分利用 tensor core 的矩阵乘；block-level 允许连续内存访问和规则的 MMA tile
  2. Routing 开销降低 N/B_k 倍：只需对 B=N/128 ≈ 8192 个 block 打分，而非 N=1M 个 token
  3. 实验证明质量无损：Paper Table 4 显示 block_size 从 32→64→128 对 PPL 几乎无影响

A.2 Index Branch 的完整算法

Index Branch 引入两组独立的投影矩阵：

Q_idx = X · W_q^idx  ∈ ℝ^{N × H_kv × d_idx}    // 4 index heads, d_idx=128
K_idx = X · W_k^idx  ∈ ℝ^{N × 1 × d_idx}       // 1 shared index key head

Step 1: Token-level scoring

S_idx^(r)_{i,j} = (Q_idx^(r)_i · K_idx_j^T) / √d_idx,    j ≤ i  (causal)

Step 2: Block-level aggregation (Max Pooling)

M_idx^(r)_{i,b} = max_{j ∈ 𝔹_b, j≤i}  S_idx^(r)_{i,j}
为什么用 max 而不是 mean/sum？

Max pooling 对应一种 upper bound 近似：如果 block 内存在至少一个 high-score token，整个 block 就值得被选中。这符合 attention 的 heavy-hitter 特性——少数 token 贡献大部分 attention mass。

Mean pooling 会被 block 内的低分 token 拉低，导致包含关键信息但被无关 padding 稀释的 block 被遗漏。Paper 在 Appendix C 未显示 score_type 的对比，但从 NSA/DSA 的经验看，max 是稀疏注意力 block scoring 的标准选择。

Step 3: Top-k Selection + Local Block

I_i^(r) = TopK_{b ∈ {1,...,B}} (M_idx^(r)_{i,·}, k)  ∪  {local_block(i)}

其中 local_block(i) = ⌈i/B_k⌉，即包含当前 position 的 block 总是被选中。

Step 4: Main Branch Sparse Attention

O_i^(h) = softmax(Q_i^(h) · K^(r)[I_i^(r)]^T / √d_h) · V^(r)[I_i^(r)]

其中 h ∈ H_r (group r 的所有 16 个 query heads 共享同一组 selected blocks)

A.4 近似误差分析

问题：MSA 跳过了未被选中的 block，这引入了怎样的误差？

理论框架

设 full attention weight 为 α_{t,i}，sparse attention weight 为 α̃_{t,i}（未选中的 block 权重为 0）：

Sparse error = ‖o_t^full - o_t^sparse‖

            = ‖Σ_{i∈I} α_{t,i}·v_i  +  Σ_{i∉I} α_{t,i}·v_i  -  Σ_{i∈I} α̃_{t,i}·v_i‖

误差来源两部分：

  1. Missing mass：被丢弃 block 中 token 的 attention weight 之和 = Σ_{i∉I} α_{t,i}
  2. Renormalization distortion：选中 token 的 softmax 在 restricted set 上重新归一化
为什么 MSA 的近似误差很小？

Attention 的 heavy-hitter 特性：在实际 LLM 中，大部分 attention mass 集中在极少数 token 上。Paper Figure 5 的可视化显示，learned indexer 准确捕获了 attention sink（首 token）、local diagonal、以及少量 long-range stripes。

定量验证：MSA-PT (from scratch) 在 3T token 训练后，LM loss 与 full attention 几乎重合（Figure 2 inset），证明信息损失可忽略。

Compute Reduction 推导

F_GQA(N)  = 2·H_q·d_h·N²                    // full causal attention

F_MSA(N)  = H_kv·d_idx·N²                    // Index Branch (lightweight quadratic)
          + 4·H_q·d_h·N·k·B_k               // Main Branch (linear in N!)

代入 M3 参数:
  H_q=64, H_kv=4, d_h=128, d_idx=128, k=16, B_k=128, N=1M

F_GQA  = 2·64·128·(10^6)²  = 16.384 × 10^15
F_MSA  = 4·128·(10^6)²     = 0.512 × 10^15   // Index Branch
       + 4·64·128·10^6·16·128 = 67.109 × 10^12  // Main Branch

Ratio = F_GQA / F_MSA ≈ 16.384T / (0.512T + 0.067T) ≈ 28.3×
关键 insight：Index Branch 仍然是 O(N²)，但系数极小（H_kv·d_idx = 512 vs H_q·d_h·2 = 16384，差 32 倍）。Main Branch 变为 O(N·k·B_k)，是关于 N 的线性复杂度。在 N=1M 时 Index Branch 仍占主导 FLOPs，但绝对值已很小。

A.5 训练 Index Branch 的关键设计

问题：Top-k 不可微

TopK 操作是离散的（选中/未选中），梯度无法回传到 W_q^idx 和 W_k^idx。需要额外的训练信号。

解法：KL Alignment Loss

定义 Index 分布 (on selected tokens I_tok):
  P_idx^(r)_{i,j} = exp(S_idx^(r)_{i,j}) / Σ_{u∈I_tok} exp(S_idx^(r)_{i,u})

定义 Main Branch 教师分布 (group-averaged):
  P^(r)_{i,j} = (1/G) · Σ_{ℓ∈H_r} [exp(S^(ℓ)_{i,j}) / Σ_{u∈I_tok} exp(S^(ℓ)_{i,u})]

KL loss:
  L_KL = (1/N·H_kv) · Σ_i Σ_r DKL(stopgrad(P^(r)_i) ‖ P_idx^(r)_i)
三个关键稳定性设计：
  1. Gradient Detach (stopgrad on X)：Index Branch 的输入是 stopgrad(X)，使 KL loss 只更新 W_q^idx 和 W_k^idx，不影响 backbone。否则 KL 梯度会通过 residual stream 干扰 backbone 训练，导致 gradient spike 或 general ability 退化。[Paper Figure 8, 9]
  2. Indexer Warmup：训练前 40B tokens 使用 full attention（Main Branch），同时用 KL loss 训练 Index Branch。避免早期随机 selection 导致 Main Branch 学习到垃圾 representation。[Paper Figure 10, 11]
  3. Forced Local Block：总是包含当前 query 所在的 block，保证 local context 可用，防止极端的 selection failure。

A.6 Index Branch 实现中的 Hadamard Transform

从 sglang DSA indexer 代码中可以看到，Q_idx 和 K_idx 在 RoPE 之后还要经过 Hadamard transform：

def rotate_activation(x):
    hidden_size = x.size(-1)
    return hadamard_transform(x, scale=hidden_size**-0.5)
Hadamard Transform 的作用：

Hadamard transform 是一个正交变换，将特征在各维度上均匀分散。这有两个好处：

  1. 降低量化误差：FP8 index cache 量化时，均匀分布的特征比集中在少数维度的特征量化损失更小
  2. 改善 max-pooling scoring：避免个别维度主导点积结果，使 block score 更稳定

注意这是 DSA（DeepSeek Sparse Attention）的实现细节，MSA paper 本身未提及 Hadamard。SGLang 的 DSA indexer 同时支持 MSA 和 DSA 模型。

Part B: MoE Routing — Sigmoid vs Softmax 与 Load Balancing

B.1 MoE Routing 的数学表达

Input:    x ∈ ℝ^{d_model}         // 单 token 的 hidden state
Gate:     logits = x · W_gate    // W_gate ∈ ℝ^{d_model × E}, E=128 experts
Score:    s_e = σ(logits_e)      // sigmoid, 每个 expert 独立打分
Bias:     s_e' = s_e + bias_e    // e_score_correction_bias
TopK:     selected = TopK(s', 4) // 选 4 个 expert
Weights:  w_e = s_e' / Σ_{e∈sel} s_e'  // renormalize
Output:   y = 2.0 · Σ_{e∈sel} w_e · Expert_e(x) + SharedExpert(x)

为什么 M3 选择 Sigmoid？

当 E=128、top-k=4 时，softmax 会将绝大部分概率集中在 1-2 个 expert 上（128 路竞争太激烈）。Sigmoid 让每个 expert 独立判断 relevance，配合 bias correction 能更好地平衡 load。这与 DeepSeek-V3 的设计思路一致。

B.3 Bias Correction 机制

e_score_correction_bias: ℝ^{128}   // per-expert learnable scalar

作用：s_e_adjusted = sigmoid(logit_e) + bias_e

如果某 expert 被选中过少 → bias 会在训练中增大 → 增加被选概率
如果某 expert 被选中过多 → bias 减小
对比 DeepSeek-V3 的 auxiliary-loss-free balancing：

DeepSeek-V3 使用完全相同的 sigmoid + bias correction 设计（它们称之为 auxiliary-loss-free load balancing）。核心 insight 是：bias 提供了一个低带宽的反馈通道，让系统可以在不引入额外 loss 项的情况下动态调整 expert 负载。

传统方法（如 Switch Transformer）需要一个 auxiliary load balancing loss，它与 LM loss 的权重调节是一个 hyperparameter headache。Bias correction 将负载均衡内化到 routing score 本身。

B.4 Routed Scaling Factor = 2.0

output = routed_scaling_factor × Σ w_e · Expert_e(x) + SharedExpert(x)
       = 2.0 × routed_output + shared_output

为什么要乘 2.0？

Sigmoid 输出范围是 (0,1)，renormalize 后 4 个 weights 之和 = 1。但因为 sigmoid score 通常在 0.5~0.9 之间（不像 softmax 那样有 winner 接近 1），实际 expert 输出的 effective scale 被压缩了。Factor 2.0 补偿这个幅度损失，使 MoE layer 的输出幅度与 residual stream 匹配。

对比：DeepSeek-V3 的 routed_scaling_factor = 2.5（因为它 top-8 选 256，sigmoid 值平均更低）。

Part C: MSA (GQA + Sparse) vs MLA (Latent Compression) — 两条路

C.1 问题本质：长 context 下 KV Cache 的两难

推理时的核心瓶颈：KV Cache 大小 = N × H_kv × d_h × 2（K和V）× num_layers × dtype_bytes

MiniMax M3 @ 1M context (bf16):
  KV cache = 1M × 4 × 128 × 2 × 60 × 2B = 122.9 GB  (full)
  With MSA: 只需缓存被索引的 block，但 KV cache 仍全量存储以供 index

DeepSeek-V3 @ 128K context (bf16):
  KV cache = 128K × 1 × 512 × 2 × 61 × 2B = 16.0 GB  (MLA compressed)

两种思路完全不同：

MSA (MiniMax M3)MLA (DeepSeek-V3)
核心策略保留完整 KV，选择性读取压缩 KV 到低秩 latent
KV 存储全量存储（+ index cache）只存 latent c_kv（512 dim）
Compute 节省attention 计算量降 28×attention 计算量不变，KV 带宽降
Memory 节省不节省 KV 存储（但节省 attention 计算的中间内存）KV cache 大幅压缩

C.2 MLA 快速回顾

DeepSeek-V3 MLA:
  c_kv = x · W_DKV           // (N, 512) latent
  k = c_kv · W_UK            // (N, H_kv, d_h) on-the-fly reconstruct  
  v = c_kv · W_UV            // (N, H_kv, d_h) on-the-fly reconstruct

KV cache 只存 c_kv (512 dim) 而非 k+v (2 × H_kv × d_h)

核心 Tradeoff 总结：
  • MSA 的优势：Attention compute 线性化（decode 尤其明显），1M context 下 wall-clock speedup 显著。质量与 full attention 持平。
  • MSA 的劣势：KV cache 不压缩，memory 占用大；需要定制 kernel；Index Branch 训练复杂；可能遗漏重要 block（尽管实验显示影响极小）。
  • MLA 的优势：KV cache 压缩到 1/2~1/4；无信息遗漏风险；标准训练无需额外 loss；kernel 兼容性好。
  • MLA 的劣势：Attention compute 仍然 O(N²)；超长 context (>128K) 下 compute 成为瓶颈；需要 on-the-fly decompress 增加 decode 延迟。

C.4 为什么两者不矛盾？可以组合

注意：MSA 和 MLA 解决的是不同层面的问题：
  • MLA 解决的是 KV cache memory（存储效率）
  • MSA 解决的是 attention compute（计算效率）

DeepSeek-V3.2 已经在 MLA 基础上加入了 DSA (DeepSeek Sparse Attention)，说明两者可以叠加：先压缩存储，再稀疏计算。

但 MiniMax M3 选择 GQA 而非 MLA 作为 base attention 有其考量：

  1. GQA 实现简单，kernel 生态成熟
  2. MSA 的 Index Branch 本身与 GQA 的 group 结构天然匹配（per-group 独立 selection）
  3. MLA 的 on-the-fly decompress 在 1M context decode 时增加延迟，与 sparse selection 的目标冲突

Partial RoPE 的信息论直觉：

一个 head 的 128 维可以被理解为两种互补信号：

  • 前 64 维 (with RoPE)：位置感知 → 编码相对距离、顺序关系、local pattern
  • 后 64 维 (no RoPE)：位置不变 → 编码语义相似性、跨距离的概念匹配

这让 attention score = position_similarity + semantic_similarity 两部分叠加。在 block scoring 时，semantic 维度帮助 Index Branch 找到语义相关但物理距离远的 block。

检验理解

Q1: MSA 的 Index Branch 为什么 K 只有 1 个 head，而 Q 有 4 个？

答：K 被所有 4 个 GQA group 共享（N×1×d_idx），每个 group 有自己的 Q head (N×1×d_idx per group)。这样每个 group 用自己的 Q 对共享的 K 打分，得到 group-specific 的 block selection。如果 K 也是 per-group，则参数和计算量翻 4 倍，但实验表明共享 K 足够（因为 K 的角色只是提供 token 的通用表征供各 group 的 Q 来查询）。

Q2: 如果把 block_size 从 128 减小到 32，会发生什么？

答：选 16 blocks × 32 tokens = 512 tokens/query（vs 原来的 2048）。要保持相同 budget 需 k=64。Block 数量从 8K→32K，Index Branch 计算不变（仍是 token-level scoring 后 max-pool），但 top-k 在 32K candidates 上选 64 个更昂贵。Paper Table 4 显示 block 32 vs 128 在相同 total budget 下质量几乎无差异，但小 block 的 kernel 效率更差（MMA arithmetic intensity ∝ B_k）。

Q3: 为什么 M3 用 Sigmoid routing 而非 Softmax？用一句话解释核心区别。

答：Softmax 让 128 个 expert 零和竞争导致 winner-take-all 的 load 不均衡；Sigmoid 让每个 expert 独立评估 token 的 relevance，配合 bias correction 天然实现负载均衡，无需额外 auxiliary loss。

Q4: DeepSeek-V3 如果要处理 1M context，面临什么瓶颈？MSA 如何规避？

答：MLA 虽然压缩了 KV cache 存储，但 attention compute 仍是 O(N²)。1M context 下 prefill 的 attention FLOPs 爆炸。MSA 将 Main Branch 变为 O(N·k·B_k) 线性复杂度，decode 时每个 token 只读 2K tokens 的 KV，wall-clock 延迟不随 context 增长。这也是为什么 DeepSeek 后来在 V3.2 中引入了 DSA。
