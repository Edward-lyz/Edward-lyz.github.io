Part 1: KV-Outer vs Q-Outer — Sparse Attention 的迭代顺序选择

1.1 问题背景

Sparse attention 的 Main Branch 需要计算：对于每个 query token，仅对其 selected blocks 做 attention。这里有一个关键的 kernel 设计选择：外层循环迭代什么？

graph LR subgraph "Q-Outer (FlashAttention 风格)" QO1["for each query token q_i:"] --> QO2["gather its selected K,V blocks"] QO2 --> QO3["compute attention(q_i, K_sel, V_sel)"] QO3 --> QO4["write O_i"] end subgraph "KV-Outer (MSA 选择)" KVO1["for each KV block b:"] --> KVO2["find all queries that selected b"] KVO2 --> KVO3["gather those queries"] KVO3 --> KVO4["compute score(Q_gathered, K_b, V_b)"] KVO4 --> KVO5["scatter partial results to O_buf"] end

1.2 IO 分析：为什么 KV-Outer 胜出

设 H_q=64, H_kv=4, G=16 (GQA ratio), d_h=128, N=1M, B_k=128, k=16。元素大小 2 bytes (bf16)。

Q-Outer IO:

FLOPs = 4·H_q·N·d_h·k·B_k           (same for both)

IO = 2·2·H_q·N·d_h                   // read Q + write O
   + 2·2·H_kv·N·k·B_k·d_h           // read K + V (per-query gather, 每个 query 读 k blocks)

Arithmetic Intensity = FLOPs / IO

分子: 4·64·N·128·16·128 = 67.1T (per token: 67.1M)
分母: 4·64·N·128 + 4·4·N·16·128·128
     = 32768N + 4194304N = 4227072N

AI = 67108864 / 4227072 ≈ 15.9 ≈ G = 16

KV-Outer IO:

FLOPs = 4·H_q·N·d_h·k·B_k           (identical)

IO = 2·2·H_kv·N·d_h                  // read K + V (each KV block loaded once)
   + 2·2·H_q·N·k·d_h                // read Q + write O_buf (queries gathered per-block)
   + 2·H_q·N·(k+1)·d_h              // read O_buf + write final O (combine phase)

分母: 4·4·N·128 + 4·64·N·16·128 + 2·64·N·17·128
     = 2048N + 8388608N + 278528N = 8669184N

AI = 67108864 / 8669184 ≈ 7.7

等等... 这算出来 Q-Outer 更好？让我重新看 paper 的分析。
Paper 的分析使用不同的简化模型：

Paper Eq.14 和 Eq.16 的 IO 模型更简洁。关键区别在于 KV 数据的重用模式：

  • Q-Outer：每个 query 需要读取 k 个不同的 KV block。由于不同 query 选择的 block 不同，KV 数据难以在 SRAM 中复用 → 每个 KV block 可能被反复从 HBM 加载
  • KV-Outer：一个 KV block 被加载到 SRAM 后，所有选中它的 query 都在此时处理 → KV 只读一次

让我重新用 Paper 的精确公式来推导：

Paper 的 Q-Outer (Eq.13-14):

FLOPs = 4·H_q·N·d_h·k·B_k

IO_Q_outer = 4·H_q·N·d_h             // read(Q) + write(O)
           + 4·H_kv·N·k·B_k·d_h     // read(K+V): 每个 query 读 k blocks, 每个 GQA group

Arithmetic Intensity = FLOPs / IO
= 4·H_q·N·d_h·k·B_k / (4·H_q·N·d_h + 4·H_kv·N·k·B_k·d_h)
= H_q·k·B_k / (H_q + H_kv·k·B_k)

代入: = 64·16·128 / (64 + 4·16·128) = 131072 / 8256 ≈ 15.9 ≈ G

Paper 的 KV-Outer (Eq.15-16):

FLOPs = 4·H_q·N·d_h·k·B_k           (same)

IO_KV_outer = 4·H_kv·N·d_h           // read(K+V): 每个 KV block 只读一次!
            + 4·H_q·N·k·d_h          // read(Q) + write(O_buf)
            + 2·H_q·N·(k+1)·d_h     // combine: read(O_buf) + write(O)

Arithmetic Intensity = FLOPs / IO
分母 = 4·H_kv·N·d_h + 4·H_q·N·k·d_h + 2·H_q·N·(k+1)·d_h
     = N·d_h·(4·H_kv + 4·H_q·k + 2·H_q·(k+1))
     = N·128·(16 + 4096 + 2176) = N·128·6288

AI = 4·64·128·16·128 / (128·6288) = 67108864 / 804864 ≈ 83.4

简化: AI ≈ (2/3)·B_k = (2/3)·128 ≈ 85.3  ✓ (matches paper)
关键结论：
方案Arithmetic Intensity含义
Q-Outer≈ G = 16受限于 GQA ratio，IO bound
KV-Outer≈ (2/3)·B_k = 85受限于 block size，接近 compute bound

KV-Outer 的 AI 是 Q-Outer 的 5.3×！这意味着 KV-Outer 更能充分利用 GPU tensor core。

直觉：Q-Outer 的瓶颈是每个 query 需要读取分散在各处的 K/V blocks（random access）。KV-Outer 让每个 KV block 只读一次，然后 gather 所有关联 query 一起计算 — query 数据是连续的、可预取的。

1.3 KV-Outer 的实现挑战

flowchart TD subgraph "Phase 1: Sparse Attention (Persistent Grid)" S1["for each (kv_block, kv_head) tile:"] S2["Reverse index: find queries that selected this block"] S3["Gather queries into SRAM (TMA copy)"] S4["Pack ⌈128/G⌉ = 8 query positions together
→ 128×128 score MMA"] S5["Compute partial attention output + LSE"] S6["Write to O_buf[slot] (pre-assigned, no atomics)"] S1 --> S2 --> S3 --> S4 --> S5 --> S6 end subgraph "Phase 2: Combine (Programmatic Dependent Launch)" C1["for each query position i:"] C2["Read k partial outputs from O_buf"] C3["Compute global LSE from partial LSEs"] C4["Weighted combine: O_i = Σ w_s · O_buf[s,i]"] C1 --> C2 --> C3 --> C4 end

Challenge 1: Sink Row (热点 block) 问题

序列开头的 block（attention sink）可能被几乎所有 query 选中。朴素映射下一个 CTA 处理一个 tile，sink block 的 CTA 负载远超其他。

解法: Pre-scheduled Tile Chunking — GPU scheduler kernel 将热 tile 沿 query 维度切分为多个 chunk（每 chunk ≤ ~2k·B_k queries），分配到多个 CTA 并行处理。每个 (query, chunk) pair 预分配一个 O_buf slot，无需 atomic。

Challenge 2: 两阶段 Forward（无法 inline softmax）

KV-Outer 下每个 query 的 k 个 partial 由 k 个不同 CTA 产生，无法在线归一化。需要：

  1. Phase 1: 每个 CTA 输出 locally-normalized partial O + LSE
  2. Phase 2: Combine kernel 读取所有 partials，用 log-sum-exp 合并： 
    LSE_global = log(Σ_s exp(LSE_s))
w_s = exp(LSE_s - LSE_global)
O_final = Σ_s w_s · O_partial_s

Challenge 3: Query Concatenation (填满 MMA tile)

KV-Outer 下每个 tile 可能只有几个 query position。单个 position 仅有 G=16 heads → MMA M维度=16，严重 under-fill。

解法：将 ⌈128/G⌉ = 8 个 query positions 拼接在一起（它们共享相同 KV block），形成 128×128 的 score MMA tile。这在 Q-Outer 中不可能做到（不同 query 选的 block 不同）。

这就是 KV-Outer 的核心优势所在：

同一 KV block 被多个 query 共享 → 可以将这些 query 拼到一起 → 增大 MMA tile → 提高 tensor core 利用率。Q-Outer 每个 query 的 block 集合不同，无法做此优化。

1.4 Exp-Free Top-k Selection

Index Branch 的 top-k 选择不需要 softmax：

关键 insight: softmax 是保序的
  s_i ≤ s_j  ⟺  softmax(s)_i ≤ softmax(s)_j

因此 top-k 可以直接在 raw scores 上做，跳过 max/exp/sum 三步。

MSA kernel: per-thread register top-k
  - 32 lanes 的 warp, 每 lane 维护一个 k=16 的 min-heap (shared memory)
  - heap root cached in register, deferred write
  - 最后 k-round shuffle merge 合并 32 个 local top-k

对比 torch.topk: 5.1× speedup @ 128K context (Table 1)

NSA 的设计哲学：多粒度并行 — 用 3 个 branch 覆盖不同的 context scale：
  • Compressed: 全局感知（大 chunk mean-pool），代价低但信息损失大
  • Selected: 精确检索（block-level top-k），代价适中，覆盖重要片段
  • Sliding window: 无条件本地，零信息损失，保证连贯性

MSA 的简化选择：去掉 compressed branch（实验发现 max-pool indexer 已足够），去掉 large sliding window（1 local block 足够），只保留核心的 index+sparse。这符合 Occam's razor 原则。

2.4 DSA: Token-Level + MLA 联合设计

All heads share same indices"] TOPK --> |"token indices"| DECODE["MLA Decode:
Decompress only selected tokens
c_kv[I] → K[I], V[I]"] DECODE --> ATT["Standard attention on selected tokens"]
DSA 的设计哲学：既然 MLA 已经压缩了 KV cache，索引可以更精细：
  • Token-level：不分 block，直接选 individual tokens。精度最高，但 kernel 优化更难（irregular access）
  • ReLU indexer：用 ReLU 代替 softmax/exp，更便宜，且 ReLU 自然稀疏（负值=0 → 天然过滤）
  • All-shared：所有 query heads 共享一组 selected tokens。简化实现，但牺牲 per-head diversity
  • 通过 LM loss 直接训练：不需要额外 KL loss（因为 indexer output 直接参与 attention 计算）

2.5 三者的关键 Tradeoff

TradeoffNSADSAMSA
Kernel 效率中 (block, 但 3 branches 的 overhead)低 (token-level irregular)高 (block + KV-outer + single branch)

MSA 的设计选择总结（Occam's Razor 原则）：
  1. 去掉 compressed branch → 实验证明 max-pool scoring 足够捕获全局信息
  2. 去掉 large sliding window → 1 local block 足够保证短程连贯
  3. 去掉 index value head → warmup + KL loss 足够训练 indexer
  4. Block-level 而非 token-level → 允许高效 KV-outer kernel
  5. Per-group 而非 all-shared → 保留 group-specific 多样性
  6. Softmax scoring 而非 ReLU → 不需要额外学习稀疏 pattern（max-pool 天然稀疏化）

结果：MSA 在保持 quality 的同时，kernel 效率最高（14.2× prefill speedup on H800），因为 block 粒度 + KV-outer + 单分支架构让 GPU 利用率最大化。

3.3 关键实现细节

3.3.1 Dual-Stream 优化

代码路径： Indexer.forward_cuda()

当 token 数 ≤ 1024 时（decode 或小 batch），Q 和 K 的计算可以在两个 CUDA stream 上并行：

  • Main stream: wq_b → Q reshape → partial RoPE → Hadamard → FP8 quant
  • Alt stream: wk → K norm → partial RoPE → Hadamard → store to index K cache

Deep GEMM 用半数 SM (half_device_sm_count) 限制每个 stream 的 SM 占用，防止 over-subscription。

3.3.2 FP8 量化 Index Cache

Index K cache 存储格式:
  - page_size = 64 (CUDA) 或 1 (HIP legacy)
  - head_dim_with_sf = 132 = 128 dim + 4 bytes scale factor
  - 存储: k_fp8 (float8_e4m3fn) + k_scale (float32, per-group)

量化 (act_quant triton kernel):
  - 按 block_size=128 分组
  - 每组计算 amax → scale = amax / 448.0
  - Clamp to [-448, 448] → cast float8_e4m3fn
  - 可选: round scale to power-of-2 (更 hardware-friendly)

3.3.3 MQA Logits 计算

核心调用： deep_gemm.fp8_mqa_logits(q_fp8, kv_fp8, weights, ks, ke) 或 deep_gemm.fp8_paged_mqa_logits(...)

这是 Index Branch 的 block scoring 实现。输入：

  • q_fp8: [num_tokens, n_heads, head_dim] FP8 量化的 index Q
  • kv_fp8: FP8 index K cache (page_size=64 布局)
  • weights: [num_tokens, n_heads] head gate weights（= weights_proj(x) × softmax_scale × q_scale）
  • ks, ke: 每个 token 的 KV range [start, end)

输出 logits ∈ ℝ^{num_tokens × max_kv_len}，然后交给 topk_transform 选择 top-k。

3.3.4 Head Gate Weights

weights = weights_proj(x) * n_heads^(-0.5) * q_scale * softmax_scale

其中:
  weights_proj: Linear(hidden_size → n_heads)  // 将 hidden 投影到每个 index head 的 gate
  n_heads^(-0.5): 归一化（类似 multi-head attention 的 1/√h）
  q_scale: FP8 量化的 scale factor（补偿量化误差）
  softmax_scale: = d_idx^(-0.5)

这个 weight 本质上是: 每个 index head 对当前 hidden state 的 importance score。
最终 logits = Σ_h weight_h × (q_h · k) ≈ 加权的 multi-head attention score。
对比 Paper 的公式：

Paper 中 block score 是简单的 max(Q_idx · K_idx / √d)。SGLang 实现中额外引入了 weights_proj，这是一个 per-head gating mechanism，让不同 head 对不同 token 有不同的 scoring 权重。这可能是 DSA/MSA 在工程实现中的增强。

3.3.5 TopK Transform

metadata.topk_transform(logits, k) → token indices

三种后端:
  1. sgl_kernel: fast_topk_v2 / fast_topk_transform_fused
     - Fused: topk + page_table lookup 一步完成
     - 最快路径

  2. flashinfer: flashinfer.top_k_page_table_transform
     - 支持 deterministic 模式
     - 带 tie-break 策略

  3. torch: torch.topk fallback
     - 最慢，仅作 reference

Transform 将 raw topk indices 转换为:
  - PAGED: page table 中的 slot index (for decode)
  - RAGGED: ragged tensor 中的 token offset (for prefill)

检验理解

Q1: KV-Outer 比 Q-Outer 的 Arithmetic Intensity 高 5× 的根本原因是什么？

答：Q-Outer 中每个 query 读取 k 个分散的 KV blocks（各 query 的 block 集合不同，无法共享 SRAM 中的 KV）。KV-Outer 中每个 KV block 只从 HBM 读一次，然后服务所有选中它的 query — query 可以拼接形成大 MMA tile。IO 中占大头的 KV read 从 O(H_kv·N·k·B_k·d_h) 降为 O(H_kv·N·d_h)（减少 k·B_k 倍），同时 query concatenation 让 MMA M-dim 从 G=16 增长到 128。

Q2: NSA 有 3 个 branch，MSA 只有 2 个。MSA 为什么能省掉 compressed branch 而不损失质量？

答：MSA 的 Index Branch 使用 max-pool scoring 对全 context 打分（仍然 scan 所有 blocks），本身就获得了全局信息感知。而 NSA 的 compressed branch 用 mean-pool 获取粗粒度全局 context — MSA 的 index branch 天然覆盖了这个功能（只是不产生 attention output，仅产生 selection decision）。实验（Paper Table 2）证明 MSA-PT 在所有 benchmark 上与 full attention 持平或更好。

Q3: DSA 用 ReLU indexer 而 MSA 用 softmax-based indexer。各自的优劣是什么？

答：
ReLU: 计算更便宜（无 exp/sum），天然稀疏（负值=0 自动过滤），可通过 LM loss 直接训练（参与 attention 计算路径）。但 ReLU 的 scoring 缺乏归一化 → 对 scale 敏感，不同 head/layer 的 score 不可比。
Softmax-based (MSA): 归一化使 score 可解释为概率，max-pool 提供了明确的语义（block 内最大相关性）。但需要额外 KL loss 训练（top-k 不可微），且 softmax 有 exp 开销。MSA 通过 exp-free top-k（利用保序性跳过 exp）弥补了这个劣势。

Q4: SGLang DSA Indexer 中的 weights_proj 在 Paper 的 MSA 公式中对应什么？

答：Paper 中 MSA 的 Index Branch score 是简单的 Q_idx · K_idx / √d_idx。SGLang 实现中 weights_proj 将 hidden state 投影为 per-head gate（类似 cross-attention 中的 gate），然后 logits = Σ_h gate_h × (q_h · k)。这等价于给 multi-head indexer 的每个 head 一个 data-dependent 的 importance weight，是对 Paper 公式的工程增强。在 MiniMax 模型的 config 中体现为 index_q_proj + weights_proj 两组独立投影。
