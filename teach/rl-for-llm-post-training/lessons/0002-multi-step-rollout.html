Lesson 02

多步决策与 Rollout

从一步选择扩展到生成一整段文本

1. 上一课的局限

上一课讲了一步选择：选一个选项，拿一个分数。但 LLM 不是选择题——它一次生成几百个 token。

问题变成：一串连续动作的策略梯度怎么算？

2. Trajectory：一串动作的完整记录

把模型从开始到结束的完整执行过程叫做一条 trajectory（轨迹）：

τ = (s₀, a₀, s₁, a₁, s₂, a₂, ... , sT)

对 LLM 来说：

符号在 LLM 中是什么
s₀用户 prompt
a₀第一个生成的 token
s₁prompt + 第一个 token（新的上下文）
a₁第二个生成的 token
...不断扩展
sT完整的 prompt + 回答

每一步的「状态」就是当前已有的全部文本，「动作」就是下一个 token。

3. Rollout：用当前策略实际跑一条 trajectory

Rollout = 让模型按当前参数 θ，实际生成一条完整输出。

不是假设、不是计算、不是查表——是真的让模型跑一遍，产生实际的 token 序列。

为什么要强调「实际跑」？因为 policy gradient 公式中的期望：

∇θ J = Eτ~πθ [ R(τ) · ∇θ log πθ(τ) ]

没法精确计算（动作空间太大），只能用采样近似。每一条 rollout 就是一个样本。

4. 序列概率 = 条件概率的乘积

自回归 LLM 的核心性质：

πθ(y₁, y₂, ..., yT | x) = πθ(y₁|x) · πθ(y₂|x,y₁) · πθ(y₃|x,y₁,y₂) · ...

简写为：

πθ(y|x) = ∏t=1T πθ(yt | x, y<t)

这不是 RL 的假设，是自回归模型本身的数学结构。取 log 后乘积变求和：

log πθ(y|x) = Σt=1T log πθ(yt | x, y<t)

5. 多步 Policy Gradient

把序列概率代入 policy gradient 公式：

∇θ J = Ey~πθ [ R(x, y) · Σt ∇θ log πθ(yt | x, y<t) ]

和上一课的一步公式对比：

一步多步
E[ R(a) · ∇log π(a) ]E[ R(y) · Σt ∇log π(yt|...) ]
采样一个动作采样一整条序列（rollout）
一个 reward整条序列结束后一个 reward

结构完全一样，只是把「一个动作」换成了「一串动作的乘积」。

6. 实际训练的近似

期望不可能精确算（所有可能的输出序列数量是天文数字）。实际做法是采样 N 条 rollout 取平均：

∇θ J ≈ (1/N) Σi=1N Ri · Σt ∇θ log πθ(yi,t | x, yi,<t)

这就是为什么：

没有 rollout，就没有办法估计 policy gradient。

Rollout 不是可选的辅助手段，它是 on-policy RL 梯度估计的数学必需品。

7. 长序列的困难：credit assignment

假设模型生成了 500 个 token，最后测试通过了，reward = 1。

公式会给这 500 个 token 全部乘以 R=1：

token 1: ∇log π(y₁) × 1  ← 有用吗？
token 2: ∇log π(y₂) × 1  ← 有用吗？
...
token 237: ∇log π(y₂₃₇) × 1  ← 这个可能是关键修复
...
token 500: ∇log π(y₅₀₀) × 1  ← 可能只是收尾

所有 token 得到同样的 reward 加权，但不是所有 token 都同样重要。这就是 credit assignment 问题：500 步里到底是哪一步起了作用？

这个问题后面会用 value function 和 advantage 来缓解（Lesson 03 内容）。

8. 三种 rollout 的区分

回到 GPT Pro 分析中的关键区分：

类型谁生成用途
Teacher rolloutClaude 或其他教师模型SFT 冷启动、离线蒸馏
RL rollout当前正在训练的模型自己Policy gradient 梯度估计
OPD rolloutStudent 生成，Teacher 在 student 的状态上指导On-policy distillation

「不再需要 Claude 的 rollout」≠「不再需要 rollout」。

前者说的是不再需要教师生成示范；后者如果成立，就意味着 on-policy RL 本身停止了。两者是完全不同的命题。

检验理解 ✍️

假设一个 LLM 对同一个 prompt 生成了 4 条 rollout，reward 分别是 [0, 0, 0, 0]。此时 policy gradient 的估计值是多少？

零向量，模型从这批数据学不到任何方向
负方向，因为全失败说明当前策略差，应该反向更新
取决于模型内部的 entropy 项，不一定为零
无法确定，必须有正有负的 reward 才能计算梯度

9. 本课小结

  1. Trajectory = 完整的状态-动作序列
  2. Rollout = 用当前策略实际生成一条 trajectory
  3. 多步 policy gradient = R · Σ ∇log π(yt|...)，结构和一步相同
  4. On-policy RL 必须有 rollout，这是梯度估计的数学需求
  5. Credit assignment：长序列里每个 token 都被乘以同一个 R，这很粗糙

下一课解决第 5 点：怎么用 value function 和 advantage 给不同 token 分配不同的「功劳」。
