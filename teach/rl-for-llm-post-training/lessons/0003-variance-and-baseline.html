Lesson 03

方差、Baseline 与 Advantage

让 policy gradient 从「能用」变成「好用」

1. 裸 Policy Gradient 的问题

上一课推出的公式：

∇θ J ≈ (1/N) Σi Ri · Σt ∇θ log πθ(yi,t | ...)

实际用起来有两个大问题：

  1. 方差极高：不同 rollout 的 R 差异很大，梯度估计忽左忽右
  2. Credit assignment 粗糙：所有 token 乘同一个 R，好坏不分

先用一个数字例子感受方差问题。

2. 方差到底多大

假设对同一个 prompt，4 条 rollout 的 reward 是：

rollout 1: R = 10  (偶然做得特别好)
rollout 2: R = 1
rollout 3: R = 2
rollout 4: R = 0

每条 rollout 对梯度的贡献正比于 R。rollout 1 的贡献是 rollout 3 的 5 倍。

但 rollout 1 可能只是运气好，不一定代表正确方向。下一批 4 条可能完全不同：

rollout 5: R = 0
rollout 6: R = 3
rollout 7: R = 0
rollout 8: R = 8

两批的平均梯度方向可能差很远。这就是高方差：估计不稳定，训练震荡。

3. Baseline：一个简单但关键的技巧

核心想法：不要用绝对 reward，用相对 reward。

∇θ J = E [ (R(a) − b) · ∇θ log πθ(a) ]

这里 b 是 baseline — 一个不依赖于当前动作的参考值。

直觉：

不问「这个动作得了多少分」，而问「这个动作比平均水平好多少」。

得 5 分，但平均水平是 8 分 → 这其实是个差动作（5−8 = −3）
得 3 分，但平均水平是 1 分 → 这其实是个好动作（3−1 = +2）

为什么减 baseline 不改变梯度方向？

数学证明只需三行：

E[ b · ∇log π(a) ] = b · Σa π(a) · ∇log π(a)

= b · Σa ∇π(a)

= b · ∇ Σa π(a) = b · ∇(1) = 0

因为所有动作概率加起来恒等于 1，其梯度恒为零。所以减掉任何只依赖状态的常数 b，期望梯度不变。

但方差变了。选对 b 能大幅降低方差。

4. Value Function：最自然的 Baseline

最好的 b 是什么？直觉上，b 应该是「在当前状态下，按正常策略能拿到的平均分」。这正是 Value Function 的定义：

Vπ(s) = Eπ[ 从状态 s 开始，一直执行到结束，能拿的总分 ]

更正式地：

Vπ(st) = E[ rt + γrt+1 + γ²rt+2 + ... | st ]

其中 γ 是折扣因子（0到1之间），让远期 reward 衰减。LLM 后训练通常 γ≈1。

V(s) 的含义：你目前处于状态 s，按正常发挥的话，预计能拿多少分。

5. Advantage：好多少 / 差多少

定义 Q 函数：

Qπ(s, a) = E[ 在状态 s 选择动作 a 之后，能拿的总分 ]

V 是平均水平，Q 是选了特定动作后的水平。两者之差就是 Advantage：

Aπ(s, a) = Qπ(s, a) − Vπ(s)

含义极其清楚：

Advantage 值含义
A > 0这个动作比当前状态的平均表现好
A = 0这个动作和平均一样
A < 0这个动作比平均差

用 advantage 替换原始 reward，policy gradient 变成：

∇θ J = E [ Σt At · ∇θ log πθ(at | st) ]

用 advantage 替换 reward 后：
• 好于平均的动作 → 增大概率
• 差于平均的动作 → 减小概率
• 和平均一样的动作 → 不动

这比「得分高就加、得分低就不动」精确得多。

6. 一个具体例子

场景：模型在生成代码的第 50 个 token 处。

V(s₅₀) = 0.4      ← 在这个状态下，平均成功率 40%
Q(s₅₀, 写 if 判断) = 0.7  ← 如果这里写 if 判断，成功率 70%
Q(s₅₀, 直接 return) = 0.2 ← 如果这里直接 return，成功率 20%

Advantage：

A(写 if 判断) = 0.7 − 0.4 = +0.3  → 增大这个 token 的概率
A(直接 return) = 0.2 − 0.4 = −0.2  → 减小这个 token 的概率

这解决了 credit assignment：不是所有 token 都乘同一个 R，而是每个 token 根据自己对成功的贡献获得不同的 advantage。

7. Critic：谁来估计 V？

V(s) 是一个期望值，没法精确算。实际做法是训练另一个神经网络来预测 V(s)。

这个预测 V 的网络叫 Critic。整体架构叫 Actor-Critic：

组件是什么做什么
Actor生成动作的 LLM（策略 πθ）决定选什么 token
Critic预测 V(s) 的网络估计当前状态能拿多少分

注意：这里的 critic 不是用自然语言评价答案，而是输出一个数字——当前状态的预估价值。

Critic 怎么训练？用 TD (temporal-difference) error 或 Monte-Carlo return 做监督学习。细节在 PPO 那课会讲。

8. 回顾：从裸 PG 到 Actor-Critic 的进化

版本梯度公式中 R 的位置被替换为效果
REINFORCER(τ)（整条轨迹总 reward）能用，方差极高
+ reward-to-goGt（从 t 之后的 reward）稍好，去掉了过去的噪声
+ baselineGt − b方差显著降低
Actor-CriticAt = Q(s,a) − V(s)每个 token 独立评估

PPO 和 GRPO 都建立在 advantage 之上，只是估计 advantage 的方式不同。

检验理解

模型在某个状态的 V(s) = 0.6。它选了一个动作后实际拿到的 return 是 0.9。这个动作的 advantage 估计值大约是多少？模型会怎么更新？

A ≈ +0.3，增大该动作的概率
A ≈ −0.3，减小该动作的概率
A ≈ +0.9，因为 return 本身就是 advantage
A ≈ +0.6，因为 V(s) 就是 advantage

9. 本课小结

  1. 裸 policy gradient 方差很大，训练不稳定
  2. Baseline：从 reward 中减去一个参考值，不改变期望梯度，但降低方差
  3. V(s) = 从状态 s 出发的平均得分 — 最自然的 baseline
  4. Advantage A = Q − V = 这个动作比平均好多少
  5. Critic = 估计 V(s) 的网络，和生成动作的 Actor 配合使用
