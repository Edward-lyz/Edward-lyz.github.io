Lesson 04

PPO：防止更新过猛

Proximal Policy Optimization 的核心思想和公式

1. 普通 Policy Gradient 的致命问题

到目前为止的公式是：

∇θ J = E [ At · ∇θ log πθ(at | st) ]

问题是：一次更新可能把策略改得面目全非。

想象你是一个学生。考了一次试，数学题做对了，语文题做错了。合理反应是「数学再接再厉，语文多练习」。但如果反应过度：「以后只做数学不做语文」——这就过猛了。

在 RL 中，一次大更新的后果：

  1. 策略突然变化 → 之前采集的 rollout 不再代表新策略
  2. 下一轮 rollout 可能在完全不同的区域 → 训练不稳定
  3. 可能陷入局部最优或直接崩溃

PPO 的核心思想：每次更新不要离旧策略太远。

用一个 clip 操作限制新旧策略的差距，保证稳定性。

2. Probability Ratio: 衡量新旧差距

假设 rollout 是用旧策略 πold 采集的。现在要优化新策略 πθ。

定义 probability ratio：

ρt(θ) = πθ(at | st) / πold(at | st)

含义：

ρ 的值含义
ρ = 1新旧策略对这个动作的概率相同（没变化）
ρ > 1新策略更喜欢这个动作（概率变大了）
ρ < 1新策略更不喜欢这个动作（概率变小了）

如果不做任何限制，用 ratio 形式写 policy gradient：

JCPI = E [ ρt · At ]

这叫 conservative policy iteration 目标。如果 ρ 无限增大，一个高 advantage 的动作会被过度强化。

3. PPO 的 Clipped Objective

PPO 的做法：限制 ρ 的范围，不让它偏离 1 太远。

JPPO = E [ min( ρt · At , clip(ρt, 1−ε, 1+ε) · At ) ]

其中 ε 通常取 0.1 或 0.2。clip 函数的意思是：

clip(ρ, 1−ε, 1+ε) = max(1−ε, min(ρ, 1+ε))

把 ρ 强制限制在 [1−ε, 1+ε] 范围内。

4. 分四种情况理解 clip

设 ε = 0.2，所以 ρ 被限制在 [0.8, 1.2]。

情况 1：A > 0 且 ρ < 1.2（好动作，变化不大）

ρ = 1.1, A = +2
min(1.1 × 2, clip(1.1) × 2) = min(2.2, 2.2) = 2.2
→ 正常优化，继续增大该动作概率

情况 2：A > 0 且 ρ > 1.2（好动作，但变化太大）

ρ = 1.5, A = +2
min(1.5 × 2, clip(1.5→1.2) × 2) = min(3.0, 2.4) = 2.4
→ 梯度被截断！不让你继续猛推了

情况 3：A < 0 且 ρ > 0.8（差动作，变化不大）

ρ = 0.9, A = −2
min(0.9 × (−2), clip(0.9) × (−2)) = min(−1.8, −1.8) = −1.8
→ 正常优化，继续减小该动作概率

情况 4：A < 0 且 ρ < 0.8（差动作，但已经减太多了）

ρ = 0.5, A = −2
min(0.5 × (−2), clip(0.5→0.8) × (−2)) = min(−1.0, −1.6) = −1.6
→ 梯度被截断！不让你继续猛减了

总结 PPO clip 的效果：

• 好动作：可以增大概率，但不许一次增太多
• 差动作：可以减小概率，但不许一次减太多
• 约束范围由 ε 控制，ε 越小约束越紧

5. PPO 的完整训练循环

for 每一轮:
    1. 用当前策略 π_old 生成一批 rollout
    2. 计算每条 rollout 的 reward
    3. 用 Critic 估计 V(s)，算出 advantage A
    4. 用 PPO clipped objective 更新 Actor（多个 mini-batch epoch）
    5. 用实际 return 更新 Critic
    6. 把更新后的 Actor 作为新的 π_old
    7. 回到步骤 1

注意步骤 1：每一轮都要重新生成 rollout。因为 PPO 是 on-policy 算法，旧策略的 rollout 在策略更新后就过时了。

步骤 4 中「多个 epoch」是 PPO 的一个效率技巧：同一批 rollout 可以用几个 epoch，只要 ρ 没偏离太远（这正是 clip 保证的）。

6. PPO 中 Critic 的训练

Critic 的任务：预测 V(s) 尽可能接近真实 return Gt。

Lcritic = (1/N) Σ ( Vφ(st) − Gt )²

这就是一个普通的 MSE 回归问题。Critic 看到状态（已有文本），输出一个数字（预估得分），和实际 return 算 L2 loss。

在 LLM 后训练中，Critic 通常和 Actor 共享大部分参数（同一个 transformer），加一个输出 head 来预测 value。

7. 为什么 PPO 在 LLM 后训练中如此流行

PPO 的优点对 LLM 训练的意义
更新步幅受控LLM 训练代价极高，一次崩溃损失巨大
可复用 rollout 几个 epochrollout 生成慢（LLM 推理），复用提高效率
实现相对简单工程可维护
token-level advantage能对长序列中的每个 token 精细评估

ChatGPT、Claude 等模型的 RLHF 阶段都使用 PPO 或其变体。

8. PPO 的代价：需要 Critic

PPO 需要训练和维护一个 Critic 网络。对于大型 LLM：

  • Critic 本身可能和 Actor 一样大
  • 额外的显存和计算开销
  • Critic 训练不好 → advantage 估计不准 → Actor 训练受损

这正是下一课 GRPO 要解决的问题：能不能不要 Critic？

检验理解

ε=0.2。某个动作的 advantage A=+3（好动作）。新策略对它的概率是旧策略的 1.5 倍（ρ=1.5）。PPO 会怎么处理？

正常用 ρ×A = 4.5 作为 objective，因为 A>0 就该大力推
clip 生效，objective 被截为 1.2×3=3.6，阻止继续增大概率
完全阻止更新，objective 变为零，因为偏离太远
将 A 从 3 砍到 ε=0.2，然后正常计算

9. 本课小结

  1. 普通 PG 可能一次更新过猛，导致训练不稳定
  2. ρ = πnew/πold 衡量新旧策略差距
  3. PPO clip：限制 ρ 在 [1−ε, 1+ε]，防止单次更新过大
  4. PPO 训练循环：生成 rollout → 算 advantage → clip 更新 → 重复
  5. 需要 Critic 来估计 V(s)，这是额外的成本
