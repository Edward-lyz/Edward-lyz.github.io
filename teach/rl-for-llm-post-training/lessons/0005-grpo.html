Lesson 05

GRPO：不需要 Critic 的 RL

Group Relative Policy Optimization — 用组内对比替代 Value 网络

1. PPO 的负担

回顾 PPO 的 advantage 计算：

At = Q(st, at) − V(st)

需要一个 Critic 网络来估计 V(s)。对大型 LLM 来说，这意味着：

  • 额外一个和 Actor 差不多大的模型
  • 训练 Critic 本身可能不稳定
  • Critic 不准 → advantage 不准 → 训练方向错误

GRPO 的问题：能不能完全不训练 Critic，直接从 rollout 中获得 advantage？

2. 核心思想：组内对比

对同一个 prompt x，生成 G 条 rollout：

y₁, y₂, ..., yG ← 全部由当前策略 πθ 对 prompt x 生成

每条的 reward：

r₁, r₂, ..., rG

计算组内均值和标准差：

r̄ = (1/G) Σ ri , σ = std(r₁,...,rG)

每条 rollout 的 advantage：

Âi = (ri − r̄) / (σ + ε)

GRPO 的 baseline 不是学出来的 V(s)，而是同一批 rollout 的平均 reward。

不需要额外的 Critic 网络。只需要对同一个 prompt 多跑几条，互相对比。

3. 一个数字例子

Prompt: 「解这道数学题」。生成 4 条 rollout：

RolloutRewardAdvantage
A: 正确解法，简洁1+1.0
B: 错误0−1.0
C: 错误0−1.0
D: 正确解法，冗长1+1.0

均值 r̄ = 0.5，标准差 σ = 0.5。标准化后 advantage 为 ±1.0。

效果：

  • A 和 D 中的动作概率被提高
  • B 和 C 中的动作概率被降低

关键区别：PPO 用 Critic 判断「这个状态平均能拿多少分」；GRPO 直接用同批 rollout 的实际分数平均值做参考。

4. GRPO 也用 PPO 的 clip

GRPO 的 objective 仍然有 clip，和 PPO 结构几乎相同：

JGRPO = E [ min( ρt · Âi , clip(ρt, 1−ε, 1+ε) · Âi ) ] − β · DKL(πθ ∥ πref)

区别只在于 Â 的来源：

PPOGRPO
Advantage 来源Critic 网络估计 V(s)，再算 A = Gt − V组内 reward 均值做 baseline
需要额外模型需要 Critic不需要
Advantage 粒度可以做到 token-level整条 rollout 一个值（sequence-level）
clip 机制相同相同

5. GRPO 的致命弱点

回到上一课 quiz 暗示的情况：如果同一 prompt 的所有 rollout 都失败了呢？

rewards = [0, 0, 0, 0]
r̄ = 0, σ = 0

Advantage:
Â_i = (0 − 0) / (0 + ε) ≈ 0  对所有 i

全失败时，GRPO 的 advantage 全部接近零 → 来自任务 reward 的梯度消失。

模型不知道往哪走。KL 正则项可能产生微小更新，但它不会告诉模型正确答案在哪里。

对比 SFT：即使模型自己完全做不对，教师轨迹仍然提供明确的逐 token 梯度。这就是为什么纯 RL 在低成功率时会卡住。

6. 什么时候 GRPO 有效，什么时候不行

场景GRPO 表现原因
数学题，模型已有一定成功率很好同一 prompt 下有对有错，对比信号明确
简单 coding 问题可以部分 rollout 能通过测试
复杂长程 Agent 任务困难成功率极低，几乎全失败，没有对比信号
任务耗时极长，rollout 长度差异大困难不同 rollout 难以对齐比较

7. GLM-5.2 为什么从 GRPO 转向 Critic-based PPO

GLM-5.2 的 Agent RL 面对的是：

  • 任务运行数小时
  • 涉及工具调用、代码执行、上下文压缩
  • 不同 rollout 长度和结构完全不同
  • 成功率很低

GRPO 在这种场景下的问题：

  1. 多数 prompt 全失败 → 没有梯度
  2. 即使有成功，不同 rollout 结构差异太大 → 组内对比不公平
  3. 只有 sequence-level advantage → 长轨迹中无法定位关键动作

GLM-5.2 的解决方案是回到 critic-based PPO：

  • 从单条 rollout 学习（不需要同一 prompt 下多条成功）
  • Critic 提供 token-level advantage（定位关键动作）
  • 处理 compacted sub-traces 的长度差异

GRPO 适合短任务、高成功率的场景（如数学题）。
长程 Agent 任务需要回到 Critic-based PPO，才能从稀疏成功中学习。

8. GRPO vs PPO 的选择逻辑

if 任务短 and 同一 prompt 能跑出有对有错的 rollout:
    → GRPO：省掉 Critic 的开销，工程简单

elif 任务长 or 成功率极低 or 需要 token-level 信号:
    → Critic-based PPO：虽然贵，但能从稀疏成功中榨取信息

检验理解 ✍️

同一 prompt 生成 8 条 rollout，reward 分别是 [1, 1, 1, 1, 1, 1, 1, 1]（全部成功）。GRPO 的 advantage 是多少？模型能学到什么？

Advantage 全为零，模型学不到区分好坏的信号
Advantage 全为正，会均匀增强所有动作的概率
不需要学习了，因为已经全部成功，策略已最优
会通过 KL 项产生有意义的更新方向

9. 本课小结

  1. GRPO = 用组内 reward 均值替代 Critic 作为 baseline
  2. 优点：不需要 Critic，工程简单，短任务效果好
  3. 弱点：全失败或全成功时梯度为零；只有 sequence-level advantage
  4. GLM-5.2 转向 PPO：长程 Agent 任务需要 token-level 信号和单条 rollout 学习能力
  5. 选择标准：成功率和任务复杂度决定用 GRPO 还是 PPO
