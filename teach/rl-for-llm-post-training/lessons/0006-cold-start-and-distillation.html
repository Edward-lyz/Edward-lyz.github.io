Lesson 06

冷启动、蒸馏与 RL 的因果关系

把前五课串起来，回答「蒸馏之后 RL 还受影响吗」

1. 这节课要回答的问题

学完前五课，你已经知道了 policy gradient、rollout、advantage、PPO、GRPO。现在回到最初 GPT Pro 分析的核心争论：

  1. 冷启动的教师数据（比如 Claude 轨迹）用完之后还有影响吗？
  2. 蒸馏只能用在 RL 之前吗？
  3. RL 能凭空创造能力吗？

2. SFT 冷启动到底做了什么

回忆 Lesson 02 的结论：policy gradient 需要采到有 reward 差异的 rollout 才有梯度。

如果模型做对某任务的概率极低，比如 p = 10⁻⁶，那么：

1000 条 rollout 中至少一条成功的概率 ≈ 1 − (1−10⁻⁶)^1000 ≈ 0.001

几乎采不到成功轨迹 → policy gradient ≈ 零向量 → 学不动。

冷启动（用教师轨迹做 SFT）的作用：

把成功概率从 10⁻⁶ 提到比如 0.01
1 − (1−0.01)^1000 ≈ 0.99996

冷启动的本质不是注入全部能力，而是把成功率从「采不到」提高到「RL 能持续采到并优化」的区间。

SFT 梯度 vs RL 梯度的信号密度

SFT（教师轨迹）RL (Policy Gradient)
每个 token明确梯度：∇log π(教师token)只有采到好结果才有梯度
不依赖模型自身✓ 不管模型当前多差都能学✗ 如果模型太差就采不到好结果
多样性受限于教师给的那几条轨迹模型自己探索，更多样

3. 长轨迹为什么更依赖冷启动

假设任务需要连续 20 步决策，每步做对的概率是 q。

P(整条轨迹成功) = q²⁰
每步正确率 q整条成功率 q²⁰
0.70.08%
0.81.15%
0.912.2%

每步只提高 10 个百分点，整条成功率可以提高一个数量级。

这解释了为什么 coding agent、长程搜索等任务比单步问答更依赖好的初始化：链式效应让微小的单步改善产生巨大的轨迹级差异。

4. 训练是路径依赖的

这是回答第一个问题的关键。把训练写成递归形式：

θ₁ = θ₀ − η · ∇L_teacher(θ₀)     ← 冷启动：用教师数据更新一次

τ₁ ~ π(θ₁)                         ← 用更新后的模型生成 rollout
θ₂ = Update(θ₁, τ₁, R₁)           ← RL 第一步

τ₂ ~ π(θ₂)                         ← 用再次更新后的模型生成 rollout
θ₃ = Update(θ₂, τ₂, R₂)           ← RL 第二步

...以此类推

注意因果链：

教师数据 → θ₁ → τ₁ → θ₂ → τ₂ → θ₃ → ... → θ最终

每一步的 rollout 由上一步的参数决定；上一步的参数又由再上一步的 rollout 决定。

「不再读取教师数据」只说明教师不再直接提供梯度。
但教师数据已经改变了 θ₁，θ₁ 决定了 τ₁ 的分布，τ₁ 又影响了后续所有更新。

因果影响沿着训练路径传播，不会因为「文件被删了」就消失。

类比：你高中老师不再教你了，但 ta 教给你的思维方式影响了你大学的选课、读什么书、做什么研究。影响是路径依赖的。

5. 蒸馏不止于冷启动

很多人以为蒸馏 = 冷启动。实际上有多种形式和时机：

蒸馏类型时机做什么
离线 SFT 蒸馏RL 之前用教师输出做 SFT 数据
Soft distillation任何时候用教师的概率分布（而非只是最终输出）做 KL loss
On-Policy Distillation (OPD)RL 之后student 生成 rollout，teacher 在 student 的状态上给指导
Cross-stage OPD多阶段训练末期把不同阶段的 expert 合并进一个模型

On-Policy Distillation 的关键区别

普通蒸馏：teacher 生成标准轨迹，student 模仿。

OPD：student 自己生成轨迹，teacher 在 student 实际走到的状态上给出指导。

为什么这很重要？

教师标准轨迹:  读测试 → 定位函数 → 修复 → 运行测试

Student 实际走成: 读测试 → 改错文件 → 出现新错误 → ???

普通蒸馏：student 不知道从错误状态怎么恢复（没见过这种状态）
OPD：teacher 在 student 的错误状态上告诉它下一步该怎么做

OPD 解决的是 distribution mismatch：student 部署时走到的状态，和 teacher 标准轨迹中出现的状态不一样。OPD 让 teacher 在 student 的实际分布上教学。

6. GLM-5 / GLM-5.2 的实际训练流程

GLM-5 公开描述的流程：

SFT → Reasoning RL → Agentic RL → General RL → On-policy cross-stage distillation

最后一步的 OPD 不是冷启动。它发生在所有 RL 之后，用来：

  • 把 Reasoning RL 阶段的推理能力恢复（可能被后续 RL 阶段覆盖）
  • 把 Agentic RL 阶段的工具使用能力保留
  • 合并多个 expert models 的能力进最终模型

GLM-5.2 更进一步：用 OPD 合并了十多个 expert models。

这直接证明：蒸馏不只是冷启动手段，它在 RL 后仍然发挥作用。

7. 完整图景：LLM 后训练的链条

预训练          → 基础语言能力和世界知识
    ↓
SFT / 蒸馏冷启动  → 把成功率从 ≈0 提到 RL 能工作的范围
    ↓
RL rollout       → 模型自己生成轨迹（必须有！）
    ↓
Reward / Critic  → 判断哪些动作好
    ↓
PPO / GRPO       → 调整动作概率
    ↓
后期 OPD         → 合并多个阶段/多个 expert 的能力
    ↓
最终模型

每一层都不可跳过（除非前一层已经足够强）：

  • 预训练不够强 → SFT 救不了
  • SFT 后成功率还太低 → RL 启动不了
  • RL 的 reward 有漏洞 → 学到错误行为
  • 多个阶段各有擅长 → 需要 OPD 合并

8. 回答开头的三个问题

问题 1：冷启动数据用完后还有影响吗？

有。训练是路径依赖的。教师数据改变了初始参数，初始参数决定了后续所有 rollout 的分布，进而影响全部后续更新。影响不会因为「不再读取文件」而消失。

问题 2：蒸馏只能用在 RL 之前吗？

不是。GLM-5/5.2 在 RL 之后使用 OPD 合并能力。蒸馏可以在任何阶段使用，每个阶段解决不同问题：

  • RL 前：冷启动，提高成功率
  • RL 中：可以用 teacher 做 reward model 或 advantage 的辅助信号
  • RL 后：OPD 恢复丢失能力、合并 expert

问题 3：RL 能凭空创造能力吗？

有条件地能。如果预训练模型已经有非零的成功概率（哪怕很小但能采到），RL 可以通过持续采样和优化放大这个概率。DeepSeek-R1-Zero 证明了这点。但如果成功率为零，policy gradient 就是零向量，RL 无法启动。

9. 判断技术声明的框架

学完这六课后，你应该能独立判断以下类型的声明：

声明判断依据（哪节课）
RL 后不需要 rollout错误Lesson 02: on-policy 梯度估计必须采样
RL 后不需要教师 rollout可能成立Lesson 02: 教师 rollout 和 RL rollout 是不同概念
冷启动数据删了就没影响了错误本课 §4: 路径依赖
蒸馏只用于冷启动错误本课 §5-6: OPD 发生在 RL 之后
全失败时 GRPO 能学到东西错误Lesson 05: advantage 全为零
PPO 不需要 Critic错误Lesson 04: Critic 估计 V(s) 是 PPO 的核心组件
输出像 Claude 就证明蒸馏了 Claude证据不足多个假设都能产生相似输出

检验理解

同一个 prompt 生成 8 条 rollout，8 条全部失败（reward=0）。如果改用一条正确的教师轨迹做 SFT，情况有何不同？

GRPO 梯度为零因为没有对比信号；SFT 仍有明确的逐 token 梯度因为不依赖采样
两者效果相近，因为一条教师轨迹的信息量也很有限
SFT 也需要 reward 信号，没有 reward 就和 RL 一样学不了
全失败时 RL 仍有负向梯度来压低失败动作的概率
