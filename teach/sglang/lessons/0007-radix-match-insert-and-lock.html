Radix match、insert 与 lock

学完本课，你能手工执行一次 compressed Radix Tree 的 match、node split、insert 和 root-path lock，并给出返回的 physical KV indices。

Node 同时保存 token segment 与 KV index segment

root
└─ key=[10, 20]      value=[101, 102]
   ├─ key=[30, 40]   value=[103, 104]
   └─ key=[50]       value=[205]

key 不是单 token，而是压缩后的 token segment；value 是逐位置对应的 physical KV indices。沿路径拼接 key 得到 cached token prefix，沿同一路径拼接 value 得到 Attention 可直接使用的 slot sequence。extra_key 还会隔离 LoRA、cache salt 等逻辑命名空间。依据：radix_cache.py:45-238。

Match 可能改变树结构

查询 [10, 20, 30, 99] 时，先命中第一段，再与 [30, 40] 匹配一个 token。因为 match 停在 segment 内部，树会把节点拆成 [30] 与 [40]，并返回 [101, 102, 103]。结构被细化，但 K/V buffer 没有重算；新节点只重新分段保存 physical index tensors。

before: [10,20] → [30,40]
after:  [10,20] → [30] → [40]
query:  [10,20,30,99]
match:  [10,20,30] → slots [101,102,103]

page_size>1 时 key 在 match 前向下取整到 page boundary，segment split 也只能发生在合法 page boundary。依据：radix_cache.py:355-413 与 radix_cache.py:648-703。

Insert 返回已经存在的 prefix 长度

插入 [10,20,50,60] 与 slots [301,302,305,306] 时，前两 token 已由 canonical tree slots [101,102] 表示。insert 沿已有路径走过 2，再创建新 segment [50,60]；返回 prefix_len=2。调用者据此释放重复的 [301,302]。

Tree 的价值是 canonical ownership相同 token prefix 最终由一组 physical slots 表示。否则每个 request 只保存自己的副本，Radix Tree 只是索引而没有节省显存。

依据：radix_cache.py:415-435 与 radix_cache.py:704-758。

Lock 保护的是整条 prefix path

request 命中 terminal node 后，inc_lock_ref 从该 node 一直走到 root 之前。某 node 从 0 → 1 时，其 segment 从 evictable accounting 转到 protected accounting；多个 requests 可让计数继续增加，但 physical segment 只计算一次。释放 request 时沿同一路径 dec_lock_ref，只有 1 → 0 才重新成为 evictable。

request A locks leaf: parent 0→1, leaf 0→1
request B locks leaf: parent 1→2, leaf 1→2
A finishes:          parent 2→1, leaf 2→1  still protected
B finishes:          parent 1→0, leaf 1→0  evictable again

依据：radix_cache.py:592-627。

最小自检

Match 在一个 compressed segment 内结束并触发 split，哪项描述正确？

正确。split 细分 token/index segments，physical K/V slots 仍是原来的 slots，不做模型重算。
不对。node split 是索引结构调整。它切分保存 slot ids 的 tensors，不重新执行模型，也不复制 K/V buffer。
