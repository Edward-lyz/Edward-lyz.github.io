Parallel rank algebra

学完本课，你能从 tp_size、dp_size 与 attn_cp_size 推导每个 rank 的 attention TP/DP 坐标，并避免把 DP Attention 误算成额外 GPU 维度。

先固定物理 world，再解释逻辑维度

在本课程的 pp_size=1 路径中，模型并行 world 有 tp_size 个 ranks。开启 DP Attention 时，dp_size 不是再乘出一组完整模型 replicas，而是在这个 TP world 内重新解释 attention ownership：

world_size   = tp_size × pp_size
attn_dp_size = dp_size
attn_tp_size = tp_size / dp_size / attn_cp_size

tp_rank = (attn_dp_rank × attn_cp_size + attn_cp_rank)
          × attn_tp_size + attn_tp_rank

本课程不深入 Context Parallel，但公式保留该维度，避免以后把 rank mapping 写错。约束是整除关系必须成立。依据：dp_attention.py:245-259 与 parallel_state.py:1983-2130。

例一：TP 8、DPA 8

tp_size=8, dp_size=8, attn_cp_size=1
attn_tp_size=1

TP rank:       0 1 2 3 4 5 6 7
attn_dp_rank:  0 1 2 3 4 5 6 7
attn_tp_rank:  0 0 0 0 0 0 0 0

每个 DP rank 的 attention 本地执行，不做 attention TP；但 dense MLP 或 MoE layer 仍处在原来的 8-rank model world 中。8 张 GPU 仍是 8 张，不是 64 张。

例二：TP 8、DPA 4

TP ranksattn_dp_rankattn_tp_rankAttention ownership
0, 100, 1DP shard 0 的 2-way TP
2, 310, 1DP shard 1 的 2-way TP
4, 520, 1DP shard 2 的 2-way TP
6, 730, 1DP shard 3 的 2-way TP

Attention group 的宽度是 2，但 MLP 的 TP group 宽度仍是 8。这种同一 rank 在不同 layer 使用不同 group 的设计，是理解后续 token gather 与 idle batch 的前提。

不要混淆三种 DP 说法

  • Native DP：controller 启动多个完整 worker replicas，GPU 数量通常随 replica 数相乘。
  • 外部 replicas：分别启动多个 server，再由 gateway/router 分流。
  • DP Attention：在一个 TP world 内让各 DP rank 拥有独立 requests/KV，attention 局部化，MLP 仍跨 world 协作。

同一个 --dp-size 在不同 enable flags 下可进入不同启动语义，所以读配置时不能脱离 --enable-dp-attention。依据：官方 DP/DPA guide。

先算 group，再谈 collective看到 all-reduce、all-gather 或 all-to-all 时，第一问不是通信量，而是 group members。group 算错，后面的性能模型全部无效。

最小自检

tp=16、dp=4、attn_cp=2 时，attn_tp_size 是多少？

正确。attn_tp_size = 16 / 4 / 2 = 2。
不对。按公式先除 attention DP，再除 attention CP：16 / 4 / 2 = 2。
