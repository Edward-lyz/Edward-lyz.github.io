从 v0.5.15 安全追踪 main

学完本课，你能审计二手文章与分叉代码，用 merge base、双侧 commit 集合和双侧 diff 判断哪些 runtime 结论仍适用。

冻结快照的三个点

节点本课程快照日期
v0.5.15^{commit}f63458b5beaccommit 2026-07-09，release 2026-07-10
origin/main2225817424e0本地快照 2026-07-13
merge-base9a6f8e5992042026-07-06

v0.5.15 是 annotated tag，git rev-parse v0.5.15 得到 tag object d80c135a...；要拿代码 commit 必须 peel 为 v0.5.15^{commit}。Release 页面是本课程版本依据：SGLang v0.5.15。

Tag 不是 main 的线性祖先

base 9a6f8e5
  ├─ release branch → 18 unique commits → v0.5.15 f63458b
  └─ main branch    → 219 unique commits → main 2225817

因此 git log v0.5.15..origin/main 只展示 main 可达而 tag 不达的 commits，却不能说明 tag 可以按这条序列直接升级；它也不会告诉你 release-only cherry-picks。课程快照的左右计数来自：

git rev-list --left-right --count v0.5.15...origin/main
# 18    219

正确的三点审计

BASE=$(git merge-base v0.5.15 origin/main)

# 双侧 commit 集合
 git log --left-right --cherry-pick --oneline    v0.5.15...origin/main

# release 从共同祖先改了什么
 git diff "$BASE"..v0.5.15 -- python/sglang/srt

# main 从共同祖先改了什么
 git diff "$BASE"..origin/main -- python/sglang/srt

# 只看本课程 hot areas
 git diff "$BASE"..origin/main --    python/sglang/srt/managers/scheduler.py    python/sglang/srt/managers/schedule_policy.py    python/sglang/srt/mem_cache    python/sglang/srt/layers/dp_attention.py    python/sglang/srt/layers/moe

git log A...B 表示 commit 的 symmetric difference；git diff A...B 在 Git 中近似 merge-base 到 B 的 tree diff。两者的三点语义不同，审计时显式保存 BASE 最不容易误读。

读优秀二手文章时也要做版本审计

用户提供的 SGLang 串讲文章给出了很好的 end-to-end 叙事、overlap 时间轴和 Scheduler/KV 连接，但其代码锚点接近 v0.5.5，出现 being_chunked_req、旧 pool API 等历史形态。KV Cache 工程文章给出了清晰的容量公式、优化 taxonomy、backend 读写视角与 HiCache overlap，但同时混合了 vLLM、内部 AttentionStore 和持续演进的 SGLang 实现。

article claim
→ classify as invariant / API detail / benchmark result
→ locate frozen-tag source or primary paper
→ keep invariant
→ rewrite API detail against v0.5.15
→ keep benchmark only with its hardware/workload boundary

因此本轮深化复用了文章的解释结构，没有复制其中旧代码作为事实。典型修正包括：v0.5.15 的类名是 HiRadixCache；DPA 的 dp_size 是 TP world 内 attention ownership 重解释；chunked request 与 allocator API 以固定 tag 为准。

先按不变量审查，不要逐行重读

  1. Scheduler：event loop 阶段与 prefill-first 选择是否改变。
  2. Budget：free、evictable、running reservation 的公式是否改变。
  3. KV：request row、physical slot 与 canonical Radix ownership 是否改变。
  4. DPA：rank algebra、token gather、IDLE collective contract 是否改变。
  5. EP：expert mapping、dispatch/combine 与 mode resolution 是否改变。
  6. HiCache/PD：destination ownership 与 completion frontier 是否改变。

截至该 main 快照，hot-area diff 已覆盖 Scheduler、DP Attention、DeepEP 与大规模 mem_cache refactor，所以不能把本课程的行号和所有边界直接外推到 main。应复用心智模型，再逐条重新验证不变量。

版本边界也是 correctness boundary本课程所有实现性声明默认只对 v0.5.15^{commit}=f63458b... 成立。Main 上同名函数不自动拥有相同行为。
