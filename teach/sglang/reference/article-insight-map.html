必须校正的实现表述

  • 旧文章中的 being_chunked_req 不能直接映射到 v0.5.15；固定 tag 使用 chunked_req，并在下一轮 stash 后排除未完成 request。
  • DPA 下 GPU/Scheduler 数量不是简单的 TP × DP。dp_size 在 TP world 内重解释 attention ownership，进程数要从 Engine 启动循环重新推导。
  • v0.5.15 类名是 HiRadixCache，不是文章里的 HiRadixTree。
  • Radix key 不只是裸 token id；extra_key 还隔离 LoRA、cache salt 等 namespace，page size 约束 match granularity。
  • token_to_kv_pool 既有真实 K/V buffers，也有独立 allocator；课程必须区分 storage 与 free-list ownership。
  • KV 容量公式必须使用 per-rank local KV heads 与 local request tokens；不能把全局 32 GiB 示例直接当成每张卡占用。
  • 文章中的性能倍数只对其模型、硬件、网络、上下文与请求分布成立，不作为 SGLang v0.5.15 的普遍结论。

没有纳入主线的内容

Fast constrained decoding、vLLM BlockPool/KV Connector、完整 KV sparsification survey、AttentionStore 内部实现与各类模型结构改造都很有价值，但它们不直接推进本课程的 Scheduler、KV ownership 与复杂并行目标。保留在资源列表，不扩张主调用链。

4. ownership、状态转移与 failure behavior 是否相同？
