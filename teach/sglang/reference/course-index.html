SGLang v0.5.15 系统学习路径

按模块完成 16 课、源码 trace、三个本地实验和最终 capstone；讲解连续进行，自检不阻塞后续内容。

版本与范围

课程冻结在 annotated tag v0.5.15^{commit}=f63458b5beaceabbd9d749b9fc956370e1b649e6。主线覆盖 Scheduler、KV Cache、Radix Cache、TP、DP Attention、EP/DeepEP；HiCache 与 PD disaggregation 作为 ownership 扩展。Kernel、multimodal、grammar、DLLM、完整 speculative decoding、PP/CP/DCP 与长尾 backend 不做逐文件深入。

模块一：Runtime 与 request 状态

  1. 从进程边界进入 Scheduler
  2. Req 与 ScheduleBatch 的双重生命周期

建议用时 6 小时：课程 1 小时；沿 Engine 到 normal/overlap event loop 源码 trace 1.5 小时；画 8-rank 进程图 1 小时；手工跟踪一个 request 两轮 1.5 小时；检索练习与复盘 1 小时。模块产物是一张不混淆 process、Req、batch 与 result queue 的 runtime map。

模块二：Admission、chunking 与 retraction

  1. Prefill admission 与 token budget
  2. Chunked prefill 与 retraction

建议用时 6 小时：课程 1 小时；逐行读 schedule policy 与 PrefillAdder 2 小时；完成 10 组 budget 手算 1 小时；跟踪 chunked request 三轮 1 小时；解释一次 retraction amplification 1 小时。

模块三：KV 物理布局与 allocation

  1. 两级 KV 索引
  2. KV allocation 生命周期

建议用时 6 小时：课程 1 小时；从容量公式估算 per-rank KV 45 分钟；读 memory_pool.py 与 allocator 1.5 小时；手画两个 request rows 45 分钟；跟 extend/decode/backend-write/finish 1.5 小时；闭卷复述 ownership 30 分钟。

模块四：Radix canonical ownership

  1. Radix match、insert 与 lock
  2. Radix eviction 与 Scheduler 耦合

建议用时 6 小时：课程 1 小时；手工执行三次 split/insert 1 小时；读 radix_cache.py 2 小时；运行 labs/radix_semantics_demo.py 并改输入 1 小时；解释 free/evictable/protected 1 小时。

模块五：Rank algebra 与 DPA

  1. Parallel rank algebra
  2. DP Attention ownership

建议用时 6 小时：课程 1 小时；运行 labs/rank_algebra.py 45 分钟；读 process-group 初始化 1.5 小时；跟踪 local attention 到 MLP gather 1.5 小时；画 tp8/dp4 与 tp8/dp8 collectives 1.25 小时。

模块六：EP、DeepEP 与跨 tier/实例 KV

  1. Expert Parallel 与 DeepEP
  2. HiCache 的三级 KV 生命周期
  3. Prefill-Decode Disaggregation

建议用时 6 小时：课程 1.5 小时；追 TopK 到 combine 1.25 小时；拆分 Dispatcher 与 Runner 指标 45 分钟；画 DPA+EP ownership 45 分钟；跟 L3 prefetch/load-back overlap 45 分钟；跟 PD preallocation/transfer/PREBUILT 1 小时。

模块七：实验、版本迁移与 capstone

  1. 端到端配置推导与实验矩阵
  2. 从 v0.5.15 安全追踪 main
  3. 最终 Capstone

建议用时 6 小时：课程 1.5 小时；设计固定 trace 45 分钟；完成三点版本审计 45 分钟；写端到端 request trace 1 小时；做 diagnosis 45 分钟；为 hot-path patch 建 correctness/benchmark baseline 1.25 小时。只有 capstone 证据通过后才记录最终能力。
