EAGLE：Feature-Level Autoregressive Draft

前置阅读：术语表 · 主要参考：EAGLE: Speculative Sampling Requires Rethinking Feature Uncertainty (Li et al., ICML 2024)

一图流：EAGLE Draft + Verify

1. 背景：Token-Level vs Feature-Level Draft

1.1 传统投机解码的局限

标准 speculative decoding（Leviathan 2023, Chen 2023）要求 draft model 是一个独立的语言模型——它从 token 空间到 token 空间做 autoregressive generation：

传统 draft：token → token \[\hat{x}_{k+1} \sim p^d(\cdot \mid x_1, \ldots, x_k)\]

问题在于：要让 draft model 足够准，它需要足够大（参数多、层数深）。但 draft model 越大，\(T_{\text{draft}}\) 越高，per-token latency 收益缩小。这是一个根本矛盾。

1.2 EAGLE 的核心观察

EAGLE 论文的关键 insight 来自一个实验发现：

Token 序列是高度不确定的（因为 sampling 的随机性），但 target model 最后一层的 hidden state 序列要确定得多。

即：给定 context，next token 可能有多种选择（entropy 高），但不管选了哪个 token，target model 对应的 hidden state 变化相对平滑。

因此：在 feature space（hidden state 空间）做 autoregressive 预测比在 token space 做要容易得多。

形式化表述：设 target model 第 \(L\) 层输出的 hidden state 序列为 \(\mathbf{f}_1, \mathbf{f}_2, \ldots\)，EAGLE 观察到：

Feature 的自相关性远高于 token \[H(\mathbf{f}_{k+1} \mid \mathbf{f}_1, \ldots, \mathbf{f}_k) \ll H(x_{k+1} \mid x_1, \ldots, x_k)\]

这意味着：用一个轻量网络预测下一步的 hidden state，精度远高于直接预测下一步的 token。

2. 创新点：Feature-Level Autoregression

2.1 架构设计

EAGLE 的 draft model 不是一个独立的语言模型，而是嫁接在 target model 之上的轻量 head：

组件输入输出参数规模
Fusion Layertarget hidden state \(\mathbf{f}_k\) + token embedding \(\mathbf{e}(x_k)\)融合特征 \(\mathbf{h}_k\)1 个 Linear
Draft Decoder\(\mathbf{h}_k\)（autoregressive）预测的下一步特征 \(\hat{\mathbf{f}}_{k+1}\)1 层 Transformer decoder
LM Head（共享）\(\hat{\mathbf{f}}_{k+1}\)token 分布 \(p^d_{k+1}\)复用 target 的 LM head

2.2 为什么需要 token embedding 拼接？

如果只用 \(\mathbf{f}_k\) 做预测，存在信息损失。原因是：

  • \(\mathbf{f}_k\) 是 target model 在 position k 的 hidden state，它编码了「给定 context，position k 的 token 分布」
  • 但在 speculative decoding 中，position k 的 token \(x_k\) 已经被采样了
  • 采样结果 \(x_k\) 包含了「从 \(\mathbf{f}_k\) 蕴含的分布中具体选了哪个」的信息——这是 \(\mathbf{f}_k\) 本身不包含的

所以 EAGLE 将两者拼接后投影：

Fusion：把采样结果注入 feature \[\mathbf{h}_k = W_{\text{fuse}} \cdot [\mathbf{f}_k;\; \mathbf{e}(x_k)] + b_{\text{fuse}}\]

其中 \([\cdot;\cdot]\) 表示 concat，\(\mathbf{e}(x_k)\) 是 token \(x_k\) 的 embedding（复用 target model 的 embedding table）。

3. 公式推导

3.1 一步 draft 的完整数据流

假设已知到 position k 为止的 target hidden states 和 token：\((\mathbf{f}_k, x_k)\)。

Step 1：Fusion — 将 hidden state 和实际采样 token 融合 \[\mathbf{h}_k = W_{\text{fuse}} \cdot [\mathbf{f}_k;\; \mathbf{e}(x_k)] \in \mathbb{R}^d\]

将 \(2d\) 维输入投影回 \(d\) 维。\(\mathbf{f}_k \in \mathbb{R}^d\) 来自 target model 最后一层，\(\mathbf{e}(x_k) \in \mathbb{R}^d\) 是 token embedding。

Step 2：Draft Decoder — 一层 Transformer 前传 \[\hat{\mathbf{f}}_{k+1} = \text{TransformerLayer}(\mathbf{h}_k;\; \mathbf{h}_{这一层的 KV cache 包含之前所有步的 \(\mathbf{h}\)，所以它能做 causal attention。输出 \(\hat{\mathbf{f}}_{k+1}\) 是对 target model 下一步 hidden state 的预测。

Step 3：LM Head — 从 feature space 映射到 token 分布 \[p^d_{k+1}(v) = \text{softmax}(W_{\text{lm}} \cdot \hat{\mathbf{f}}_{k+1})[v]\]

\(W_{\text{lm}}\) 直接复用 target model 的 LM head 权重（frozen），无需额外参数。

Step 4：采样 — 得到 draft token \[\hat{x}_{k+1} \sim p^d_{k+1}(\cdot)\]

采样后，\(\hat{x}_{k+1}\) 成为下一步 fusion 的输入之一。但注意：真正的 \(\mathbf{f}_{k+1}\) 不可用（那需要完整 target 前传），所以 EAGLE 用 \(\hat{\mathbf{f}}_{k+1}\) 代替。

3.2 多步 draft 的递推

生成 \(\gamma\) 个 draft token 时，后续步骤必须用自己预测的 feature 做输入——这产生了误差累积：

Step 1 (k=1)：用真实的 \(\mathbf{f}_0, x_0\) 启动 \[\mathbf{h}_0 = W_{\text{fuse}} \cdot [\mathbf{f}_0;\; \mathbf{e}(x_0)]\] \[\hat{\mathbf{f}}_1 = \text{Decoder}(\mathbf{h}_0)\] \[\hat{x}_1 \sim \text{softmax}(W_{\text{lm}} \cdot \hat{\mathbf{f}}_1)\]

\(\mathbf{f}_0\) 是 anchor token 的真实 target hidden state，精度最高。

Step 2 (k=2)：用预测的 \(\hat{\mathbf{f}}_1\) 继续 \[\mathbf{h}_1 = W_{\text{fuse}} \cdot [\hat{\mathbf{f}}_1;\; \mathbf{e}(\hat{x}_1)]\] \[\hat{\mathbf{f}}_2 = \text{Decoder}(\mathbf{h}_1;\; \mathbf{h}_0)\] \[\hat{x}_2 \sim \text{softmax}(W_{\text{lm}} \cdot \hat{\mathbf{f}}_2)\]

从此步开始，输入的 feature 是上一步的预测值，不是真值。误差开始累积。

一般情况 (k=j)：递推 \[\mathbf{h}_{j-1} = W_{\text{fuse}} \cdot [\hat{\mathbf{f}}_{j-1};\; \mathbf{e}(\hat{x}_{j-1})]\] \[\hat{\mathbf{f}}_j = \text{Decoder}(\mathbf{h}_{j-1};\; \mathbf{h}_{第 \(j\) 步的预测精度受前面所有步累积误差影响。这是 autoregressive drafter 的固有代价。

3.3 训练目标

EAGLE 的训练极其简单——直接用 target model 的真实 next-token 做 hard label cross-entropy：

Training loss \[\mathcal{L} = -\sum_{k=1}^{\gamma} \log p^d_k(x_k^*)\]

其中 \(x_k^*\) 是 target model 在该位置的真实 next token。训练时使用 teacher forcing（输入的是真实 \(\mathbf{f}_k\)，不是预测值），避免 exposure bias 导致训练不稳定。

EAGLE 的训练不需要 target model 在线推理——只需离线收集 target model 的 hidden states 作为数据集。这让训练成本很低（只训练 1 层 Transformer + 1 个 Linear）。

3.4 验证：标准 Rejection Sampling

验证阶段和标准 speculative decoding 完全一致。Target model 一次前传处理 \(\gamma\) 个 draft token，逐个验证：

对每个位置 k (从 1 到 γ)： \[\text{接受 } \hat{x}_k \text{ 的概率} = \min\left(1,\; \frac{p^t_k(\hat{x}_k)}{p^d_k(\hat{x}_k)}\right)\]

若 draft 给出的概率低于 target（draft 低估了该 token），\(\min\) 取 1，一定接受。
若 draft 过度自信（\(p^d > p^t\)），以 \(p^t/p^d\) 的概率接受——draft 越偏离 target 越容易被拒。

一旦某个位置被拒绝：

从修正分布中重新采样一个 token：\(x_k \sim \text{norm}(\max(0,\; p^t_k - p^d_k))\)，然后丢弃后续所有 draft token。

全部通过的额外 bonus：

如果 γ 个全部被接受，额外从 \(p^t_{\gamma+1}\) 采样一个 bonus token。

4. 性能分析：EAGLE 的优势与局限

4.1 优势

方面对比标准 spec decoding
Draft 精度在 feature space 预测，自相关性高 → acceptance rate 显著更高
Draft 速度只有 1 层 Transformer + 1 个 Linear → 每步延迟极低
训练成本只训练 draft head（~50M 参数），不需要从零训一个小 LM
参数共享LM head + embedding 与 target 共享 → 无额外显存占用

4.2 局限：串行瓶颈

EAGLE 的根本限制：draft 是 autoregressive 的。每一步的输入依赖上一步的输出：

\(T_{\text{draft}} = \gamma \times T_{\text{step}}\)

即使每步很快（~1ms），当 \(\gamma = 7\) 时仍需 7ms。在高吞吐场景下，这 7ms 是 target model 一次 prefill 的相当比例。

这正是后来 DFlash 和 DSpark 要解决的问题。

4.3 误差累积

多步 draft 中，position 1 用的是真实 \(\mathbf{f}_0\)，精度最高。后续位置用预测的 \(\hat{\mathbf{f}}\)，误差逐步放大：

Acceptance rate 随 position 衰减 \[c_k \approx c_1 \cdot \rho^{k-1}, \quad \rho < 1\]

这个衰减是所有 autoregressive drafter 的通病。EAGLE2 将引入 tree verification 来缓解它（下一课）。

5. 小结

EAGLE 的三个核心贡献：
① 发现 feature space 比 token space 更容易预测（entropy 更低）
② 设计 fusion layer 将采样结果注入 feature（解决信息损失）
③ 共享 LM head 将 feature 预测转为 token 分布（零额外参数）

遗留问题：串行 draft → latency 线性增长，后续位置误差累积 → acceptance rate 衰减。

6. Quiz

Q1: EAGLE 选择在 feature space 而非 token space 做 draft 的根本原因是？

✓ 正确！EAGLE 的核心观察是 \(H(\mathbf{f}_{k+1} \mid \mathbf{f}_{\leq k}) \ll H(x_{k+1} \mid x_{\leq k})\)。Feature 序列的自相关性更高，单层 Transformer 就能准确预测。
✗ Feature space 维度和 token space 维度实际相同（hidden dim ≈ vocab size 的数量级）。关键不是维度，而是序列的 smoothness / entropy。

Q2: EAGLE 的 fusion layer 为什么必须拼接 token embedding \(\mathbf{e}(x_k)\)？

✓ 正确！\(\mathbf{f}_k\) 代表「给定 context 的 next-token 分布」，不含「实际选了哪个」的信息。拼接 \(\mathbf{e}(x_k)\) 把 sampling 决策注入。
✗ Hidden state 本身已含位置编码（通过 RoPE）。拼接 embedding 的目的不是补位置信息，也不是对齐维度。

Q3: EAGLE 在多步 draft 中 acceptance rate 逐步衰减的根本原因是？

✓ 正确！Position 1 用真实 \(\mathbf{f}_0\)，精度最高。后续步骤用 \(\hat{\mathbf{f}}\)，每步的预测误差会传播并放大到下一步。
✗ LM head 对位置无感知（position-agnostic）。KV cache 包含前面所有步的 h。真正原因是 feature 的误差累积——用预测值代替真值的 error propagation。
