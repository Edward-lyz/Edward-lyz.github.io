DSpark：Semi-Autoregressive Generation

前置阅读：术语表 · Lesson 04 (DFlash)
本课目标：理解 DSpark 如何用 "base logits + sequential bias" 分解，以极低延迟代价修复 suffix decay。

一图流：DSpark 完整解码轮

1. 背景：两个极端之间的 gap

1.1 回顾：EAGLE3 vs DFlash 的根本矛盾

EAGLE3（AR drafter）DFlash（Parallel drafter）
Drafting latency\(T_{\text{draft}} = \gamma \times T_{\text{step}}\) → 慢\(T_{\text{draft}} \approx T_{\text{fwd}}(1)\) → 快
Token 间依赖完整条件链 \(p(x_k \mid x_{<k})\) → 精确独立边际 \(p(x_k)\) → suffix decay
网络深度1 层（被延迟约束）5 层（不受 γ 影响）

根本矛盾：

  • EAGLE3 的问题是时间：token 间有依赖但生成太慢
  • DFlash 的问题是质量：生成够快但没有 token 间依赖

1.2 DSpark 的设计目标

能不能在 DFlash 的 O(1) parallel backbone 之上，用极低的额外延迟注入 token 间依赖？

关键洞察：DFlash 的 backbone 输出（base logits）已经很好了——尤其在 position 1。问题只是后续位置缺少对前驱 token 具体取值的 conditioning。如果能用一个极轻量的模块，在采样阶段逐步注入一个 "修正项"，就能修复偏差而不重算 backbone。

2. 创新点：解耦生成的四阶段架构

DSpark 将 draft→verify 循环解耦为四个阶段：

#阶段做什么延迟解决什么问题
①Parallel Backbone一次前传出 γ 个位置的 base logits + hidden statesO(1)打破串行瓶颈
②Sequential Head逐步添加依赖前驱 token 的 bias 修正O(γ) 但极轻量修复 suffix decay
③Confidence Head预测每个位置的接受概率O(1) per token判断哪些值得验证
④Target Verification只验证被保留的高置信前缀取决于保留长度减少验证浪费
关键设计哲学：把 "生成质量" 和 "验证效率" 解耦成独立可优化的子问题。Sequential head 管质量，confidence head + scheduler 管效率。两者互不干扰。

3. 公式推导：Base + Bias 分解

3.1 出发点：Block 联合分布

给定 anchor \(x_0\)（上一轮 target 验证产出的最后一个 token），block 内 γ 个 draft token 的联合概率分解为链式条件概率：

链式分解（概率论基本公式） \[P(x_1, x_2, \ldots, x_\gamma \mid x_0) = \prod_{k=1}^{\gamma} p_k(x_k \mid x_0, x_1, \ldots, x_{k-1})\]
为什么是链式分解？ 这是概率论的链式法则（chain rule），不是近似。任何联合分布都可以精确分解为条件概率的乘积。这里 \(p_k(x_k \mid x_0, x_{<k})\) 表示：在已知 anchor 和前面所有 token 取值的条件下，位置 k 的条件分布。
对比 DFlash DFlash 假设各位置独立：\(P \approx \prod_k p_k(x_k \mid x_0)\)——丢掉了 \(x_{<k}\) 的条件。DSpark 要把这个条件加回来，但不能像 EAGLE3 那样做完整的 autoregressive forward。

3.2 核心设计：将条件分布分解为 base + bias

DSpark 对每个位置 k 的条件分布做如下分解：

Base + Bias 分解（DSpark 核心公式） \[p_k(v \mid x_0, x_{<k}) = \frac{\exp\bigl(U_k(v) + B_k(x_0, x_{<k}, v)\bigr)}{\displaystyle\sum_{u \in \mathcal{V}} \exp\bigl(U_k(u) + B_k(x_0, x_{<k}, u)\bigr)}\]

这个公式信息量很大，逐步拆解：

Step 1: 识别 softmax 结构 分子/分母的结构 = \(\text{softmax}(\text{logits})\)。这里的 logit 被拆成两部分之和： \[\text{logit}_k(v) = U_k(v) + B_k(x_0, x_{<k}, v)\]
Step 2: \(U_k(v)\) — Base logit（并行部分） \(U_k(v)\) 是 parallel backbone 对位置 k、token v 给出的 logit。
关键性质：\(U_k\) 不依赖 \(x_{<k}\) 的采样结果。它只依赖 anchor \(x_0\) 和 target context。
因此 \(U_k\) 可以对所有 γ 个位置一次性并行算出（和 DFlash 完全一样的计算）。
Step 3: \(B_k(x_0, x_{<k}, v)\) — Bias（串行部分） \(B_k\) 是 sequential head 给出的加性修正（bias）。
关键性质：\(B_k\) 依赖 \(x_{<k}\)（前面被采样的具体 token）。
因此 \(B_k\) 必须在 position 1 的 token 被采样后才能算 position 2 的 bias → 串行。
Step 4: 为什么用加法？ 在 log 空间（logit 空间）中，加法 = 概率空间中的乘法。即： \[p_k(v) \propto \exp(U_k(v)) \cdot \exp(B_k(v)) = p_{\text{base}}(v) \cdot \text{correction}(v)\] 这意味着 sequential head 不是重新估计整个分布，而是在 base distribution 上做乘性修正。修正因子 \(\exp(B_k(v))\) 提升一些 token 的概率、压低另一些。
Step 5: 为什么这比重新计算更好？ Backbone 的 5 层 Transformer 前传已经提取了 rich context → \(U_k\) 的质量很高（尤其 position 1 优于 AR drafter）。
Sequential head 只需做一个小修正 → 参数少、计算少 → 延迟极低。
类比：考试时先写出初稿答案（backbone），然后快速检查修改个别地方（bias），比从头重写快得多。

3.3 对比 DFlash：多了什么，少了什么？

DFlashDSpark
Position k 的 logit\(U_k(v)\) 独立\(U_k(v) + B_k(x_{<k}, v)\) 有条件依赖

3.4 Markov Head：Sequential Bias 的具体实现

理论上 \(B_k\) 可以依赖完整前缀 \(x_{<k}\)。但如果 sequential head 太重，就重新引入了 EAGLE3 的串行瓶颈。

一阶 Markov 近似：只让 bias 依赖前一个 token \(x_{k-1}\)：

Markov 近似 \[B_k(x_0, x_{<k}, v) \approx B(x_{k-1}, v)\]
为什么只看前一个 token 就够？ 直觉：在自然语言中，给定前一个 word 后，后续 word 的条件分布已经大幅收窄。
例如："of" 后面大概率是 "course"/"the"/"a"；不需要看更远的历史就能排除 "problem"。
论文实证（Figure 4）：Markov head 与 RNN head（能看全前缀）的 acceptance length 差距很小（< 3%）。
为什么不直接存一个 V×V 的转移矩阵？ 如果 \(B(x_{k-1}, v)\) 用一个完整的 \(V \times V\) 表格存储（每个前驱 token 对应一行 V 维 logit bias）：
参数量 = \(V^2 = 152{,}000^2 \approx 2.3 \times 10^{10}\)（230 亿参数）。
这比 target model 本身还大，完全不可行。
→ 需要做 low-rank 分解来压缩。

3.4.1 Low-Rank 分解的推导

将 \(V \times V\) 矩阵分解为两个小矩阵的乘积：

Low-rank Markov bias \[B(x_{k-1}, v) = \bigl(W_1[x_{k-1}]\bigr) \cdot W_2[:, v]\]

向量化写法（对所有 v 同时算）：

\[B(x_{k-1}, \cdot) = W_1[x_{k-1}] \cdot W_2 \;\in\; \mathbb{R}^V\]
Step 1: \(W_1 \in \mathbb{R}^{V \times r}\) — Embedding table \(W_1\) 是一个 embedding 矩阵，每行对应一个 token id 的 r 维表示。
给定 \(x_{k-1}\) 的 token id → lookup 第 \(x_{k-1}\) 行 → 得到向量 \(W_1[x_{k-1}] \in \mathbb{R}^r\)。
这一步的计算量 = 1 次 embedding lookup（O(1) 内存访问）。
Step 2: \(W_2 \in \mathbb{R}^{r \times V}\) — Projection matrix 将 r 维的 latent 向量投影回 V 维空间，得到每个目标 token 的 bias 值。
计算量 = 1 次矩阵乘法：\((1 \times r) \times (r \times V) = (1 \times V)\)。
Step 3: 参数量计算 \[|W_1| + |W_2| = V \times r + r \times V = 2rV\] 取 \(r = 256\), \(V = 152{,}000\)： \[2 \times 256 \times 152{,}000 = 77{,}824{,}000 \approx 78\text{M 参数}\] 对比完整矩阵的 230 亿参数 → 压缩了 \(\sim 300\times\)。
Step 4: 每步推理延迟 1 次 embedding lookup ≈ 几 μs（纯内存访问）
1 次 matmul(1, 256) × (256, 152000) ≈ 几十 μs（GPU 上一个小 GEMV）
总计 < 100 μs per step → γ = 7 步 < 0.7 ms → 远小于 backbone 的 ~20 ms 前传
Step 5: 表达力验证 Rank-256 意味着转移矩阵有 256 个自由度来区分不同的前驱 token 对后继的影响。
直觉：语言中 "前一个 word 对下一个 word 的约束" 通常只涉及少数语义维度（语法角色、语义兼容性等），远不需要 152k 维 → 256 维足够表达主要模式。

3.4.2 代码对应：VanillaMarkov 类

在 DeepSpec 代码库中（deepspec/modeling/dspark/markov_head.py）：

class VanillaMarkov(nn.Module):
    def __init__(self, *, vocab_size, markov_rank):
        self.markov_w1 = nn.Embedding(vocab_size, markov_rank)  # W1: V×r
        self.markov_w2 = nn.Linear(markov_rank, vocab_size, bias=False)  # W2: r×V

    def compute_step_bias(self, token_ids, hidden_states):
        # token_ids = x_{k-1}
        return self.markov_w2(self.markov_w1(token_ids))  # lookup + matmul

3.5 完整的采样过程（逐步）

把 parallel backbone + sequential head 合在一起，DSpark 一轮 draft 的完整流程：

Step 1: Parallel backbone forward 输入：anchor \(x_0\) + (γ-1) 个 MASK token + target context hidden states
输出：所有 γ 个位置的 base logits \(\{U_1, U_2, \ldots, U_\gamma\}\) 和 hidden states \(\{h_1, \ldots, h_\gamma\}\)
延迟：一次 5 层 Transformer 前传 ≈ 20 ms（与 γ 几乎无关）
Step 2: Position 1 — 采样第一个 token Position 1 的 prev_token = anchor \(x_0\)。计算 bias： \[B(x_0, \cdot) = W_1[x_0] \cdot W_2 \in \mathbb{R}^V\] 合并 logits 并采样： \[x_1 \sim \text{softmax}(U_1 + B(x_0, \cdot))\]
Step 3: Position 2 — 用 \(x_1\) 的结果 现在 \(x_1\) 已知（刚采样出来）。计算 position 2 的 bias： \[B(x_1, \cdot) = W_1[x_1] \cdot W_2 \in \mathbb{R}^V\] 合并并采样： \[x_2 \sim \text{softmax}(U_2 + B(x_1, \cdot))\]
Step 4: 重复直到 Position γ 对 k = 3, 4, ..., γ 依次： \[B(x_{k-1}, \cdot) = W_1[x_{k-1}] \cdot W_2\] \[x_k \sim \text{softmax}(U_k + B(x_{k-1}, \cdot))\]
延迟分析 Step 1 = ~20 ms（并行 backbone，与 DFlash 一样）
Steps 2–4 = γ × (~100 μs) ≈ 0.7 ms for γ=7
总 drafting latency ≈ 20.7 ms → 额外开销 < 4%

3.6 为什么 Bias 能修复 Multi-Modal Collision？

回到 Lesson 04 的 "of course" vs "no problem" 例子：

DFlash（无 bias） Position 2 的 base logit \(U_2\)：对 "course" 和 "problem" 给出接近的分数（因为边际化了两条路径）。
→ 采样接近 50/50 → 与 position 1 的选择可能不一致。
DSpark（有 bias）— Case 1: \(x_1\) = "of" Markov bias \(B(\text{"of"}, \cdot)\)：
  • \(B(\text{"of"}, \text{"course"})\) 是正值（W1["of"] · W2[course] > 0，因为训练数据中 "of" → "course" 频繁共现）
  • \(B(\text{"of"}, \text{"problem"})\) 是负值或接近零
合并后：\(U_2(\text{"course"}) + B(\text{"of"}, \text{"course"}) \gg U_2(\text{"problem"}) + B(\text{"of"}, \text{"problem"})\)
→ softmax 后 "course" 的概率远高于 "problem" → 几乎确定采到正确续写。
DSpark（有 bias）— Case 2: \(x_1\) = "no" 对称地，\(B(\text{"no"}, \text{"problem"})\) 为正值 → "problem" 概率被大幅提升 → 正确续写。
结论 Markov bias 根据前一个 token 的实际取值，动态调整后续 token 的概率分布 → 消除 multi-modal collision → suffix decay 显著减轻。

3.7 GatedMarkov：引入 hidden state 信息

VanillaMarkov 的 bias 只看前一个 token id。但有时 hidden state 包含 base logits 没表达的信息。

Gated Markov bias \[g_k = \sigma\bigl(W_g \cdot [h_k;\; W_1[x_{k-1}]]\bigr) \in (0, 1)^r\] \[B_k^{\text{gated}}(x_{k-1}, v) = \bigl(g_k \odot W_1[x_{k-1}]\bigr) \cdot W_2[:, v]\]
Step 1: Gate 输入 拼接当前位置的 hidden state \(h_k \in \mathbb{R}^d\) 和前驱 token embedding \(W_1[x_{k-1}] \in \mathbb{R}^r\)。
拼接结果 \(\in \mathbb{R}^{d+r}\)。
Step 2: Gate 计算 \(W_g \in \mathbb{R}^{(d+r) \times r}\) 将拼接向量投影为 r 维，再过 sigmoid → 每个维度独立得到 \(\in (0,1)\) 的 gate 值。
Step 3: 逐元素乘 \(g_k \odot W_1[x_{k-1}]\)：gate 决定 "让前驱 embedding 的哪些维度通过"。
直觉：有些前驱 token 对后续影响大（gate ≈ 1），有些影响小（gate ≈ 0）。Hidden state 提供了这个判断的 context。
Step 4: 投影回 V 维 和 VanillaMarkov 一样，gated embedding 通过 \(W_2\) 投影为 V 维 bias。
额外延迟 多了一个 Linear(d+r, r) + sigmoid + 逐元素乘。在 GPU 上增加 ~10 μs → 几乎可忽略。

3.8 RNN Head：看完整前缀（可选）

当 block 很长（γ > 7）时，一阶 Markov 可能不够。RNN head 用 GRU-like 循环状态记忆完整前缀：

RNN head 的 recurrent step \[z_k = [s_{k-1};\; W_1[x_{k-1}];\; h_k] \;\in\; \mathbb{R}^{2r+d}\] \[\text{gate}_k = \sigma(W_g \cdot z_k) \;\in\; (0,1)^r\] \[\text{candidate}_k = \tanh(W_c \cdot z_k) \;\in\; (-1,1)^r\] \[s_k = \text{gate}_k \odot s_{k-1} + (1 - \text{gate}_k) \odot \text{candidate}_k\] \[B_k(x_{<k}, v) = W_2^\top \tanh(W_o \cdot z_k)\]
Step 1: 输入拼接 \(z_k\) 三部分拼接：
• \(s_{k-1} \in \mathbb{R}^r\)：上一步的 recurrent state（记忆了 \(x_1, \ldots, x_{k-2}\)）
• \(W_1[x_{k-1}] \in \mathbb{R}^r\)：前一个 token 的 embedding
• \(h_k \in \mathbb{R}^d\)：backbone 在当前位置的 hidden state
拼接后 \(\in \mathbb{R}^{2r+d}\)。
Step 2: 联合投影 \(W_g, W_c, W_o \in \mathbb{R}^{(2r+d) \times r}\) 三个矩阵实际合并为一个 Linear(2r+d, 3r) 层，输出后 chunk 成三份。这样只做一次 matmul 而非三次。
Step 3: GRU-like state update \(s_k = \text{gate} \cdot s_{k-1} + (1-\text{gate}) \cdot \text{candidate}\)：
  • gate ≈ 1 → 保留旧记忆不变
  • gate ≈ 0 → 用新 candidate 替换旧记忆
效果：state \(s_k\) 自适应地融合了完整前缀 \(x_1, \ldots, x_{k-1}\) 的信息。
Step 4: 输出 bias \(\tanh(W_o \cdot z_k)\) 将 z_k 映射为 r 维 output latent。
\(W_2^\top\) 将其投影回 V 维 → 得到 per-token bias。
和 VanillaMarkov 的区别：bias 不仅看 \(x_{k-1}\)，还编码了整个前缀的 accumulated state。
Step 5: 初始状态 \(s_0 = \mathbf{0}\)。第一步只有 \(W_1[x_0]\) 和 \(h_1\) 的信息 → 退化为类似 GatedMarkov 的行为。随着步数增加 state 逐渐积累前缀信息。

3.10 Confidence Head 概述

（详细推导留在后续课程，这里只给接口定义）

Confidence head 输出 \[c_k = \sigma\bigl(w^\top [h_k;\; W_1[x_{k-1}]]\bigr) \in (0, 1)\]

含义：position k 在前面全部被接受的前提下，被 target 接受的条件概率估计。

用途：prefix survival probability \(a_k = \prod_{i=1}^k c_i\) → 交给 scheduler 决定验证到哪里截断。

4. Attention Mask 与 Position Encoding

4.1 DSpark Attention Mask 规则

Query 位置可以看到的 KV理由
Block 内任意位置Context（anchor 之前的已确认 token）因果性：只能看过去
Block 内位置 k同 block 内所有位置（bidirectional）并行计算需要所有位置同时处理
Block 内位置 k其他 block 的位置（训练时）不可见——各 block 独立训练

4.2 Position ID 构造

\[\text{pos\_id}(k) = \text{anchor\_position} + k, \quad k = 0, 1, \ldots, \gamma-1\]

Draft token 与 context 共享同一 RoPE 空间 → attention 中的相对位置关系与 autoregressive decoding 完全一致。

5. 小结

DSpark Semi-Autoregressive Generation 的三个关键设计：

① Base + Bias 分解：重计算（backbone）并行做完 → 轻量修正（bias）串行补上条件依赖。两者相加后做 softmax → 精确的条件分布。

② Low-rank Markov Head：V×V 转移矩阵分解为 (V×r)(r×V)，rank=256 → 78M 参数 → 每步 <100μs。

③ 极低额外延迟：γ=7 时 sequential head 总开销 < 0.7ms，相对 backbone 的 ~20ms 几乎免费（< 4% overhead）。

效果：macro-average accepted length 比 DFlash 提升 16–18%，比 EAGLE3 提升 27–31%。

6. Quiz

Q1: DSpark 相对 DFlash，在生成阶段的核心变化是什么？

✓ 正确！DSpark 和 DFlash 共享同样的 parallel backbone（深度相同）。唯一的区别是 DSpark 多了一个 sequential head，在采样时逐步加 bias。这个 bias 依赖前一个被采样的 token → 注入 token 间依赖 → 修复 suffix decay。
✗ DSpark 的 backbone 和 DFlash 一样深（都是 5 层）。变化不在 backbone 深度或验证结构，而在采样阶段加了一个轻量的串行 bias 修正。

Q2: Low-rank 分解 B = W₁·W₂ 中 rank=256 的含义是？

✓ 正确！Rank-256 = 中间 latent space 是 256 维。W1 将前驱 token 编码为 256 维向量，W2 将其解码为 V 维 bias。这是对 V×V 完整矩阵的低秩近似，256 个自由度足以捕捉主要的 token 间转移模式。
✗ Low-rank 不是限制 token 数量。所有 V=152k 个 token 都有对应的 embedding 和 bias 输出。256 是中间 latent 维度——信息的瓶颈宽度。

Q3: Base+Bias 分解在概率空间的含义是什么？

✓ 正确！Logit 空间的加法 = 概率空间的乘法：p(v) ∝ exp(U(v)) × exp(B(v))。如果 B(v) > 0 → 该 token 概率被提升；B(v) < 0 → 被压低。这不是 mixture，是乘性 re-weighting 后重新归一化。
✗ Logit 加法 ≠ 概率加法（那是 mixture）。exp(U+B) = exp(U)·exp(B) → 概率空间是乘法关系。Bias 也不只是缩放——它改变了不同 token 的相对排序。

7. Confidence-Scheduled Verification（DSpark 特有）

标准 speculative decoding 对每个 request 固定验证全部 γ 个 draft token。DSpark 打破这个约束：用 confidence head 预测每个位置的接受概率，配合 hardware-aware scheduler 动态决定每个 request 验证多长——给高质量 draft 多验证，低质量 draft 早截断。EAGLE/EAGLE2/EAGLE3/DFlash 都没有这个组件。

7.1 Confidence Head 结构

Confidence head forward（每位置 k） \[c_k = \sigma\!\bigl(w^\top [h_k;\; W_1[x_{k-1}]]\bigr) \;\in\; (0, 1)\]
结构拆解 \(h_k \in \mathbb{R}^d\)：backbone hidden state。\(W_1[x_{k-1}] \in \mathbb{R}^r\)：Markov embedding。拼接后过一个线性层 + sigmoid → 输出标量 \(\in (0,1)\)。
参数量 = \(d + r \approx 4352\)（极轻量，复用 Markov head 的输入）。每步推理延迟 < 1 μs。
训练 target \(c_k^* = 1 - \text{TV}(p_k, q_k) = \sum_x \min(q_k(x), p_k(x))\)。训练时有 target model 做 teacher → 算出真实接受率作标签，用 BCE loss 训练。

7.2 吞吐最大化目标函数

给定 \(R\) 个活跃 request，每个分配验证长度 \(\ell_r \in \{0, \ldots, \gamma\}\)。目标：

System throughput \[\Theta = \underbrace{\left(\sum_{r=1}^R \tau_r\right)}_{\text{每步产出}} \cdot \underbrace{\text{SPS}(B)}_{\text{每秒步数}}, \quad B = \sum_{r=1}^R (1 + \ell_r), \quad \tau_r = 1 + \sum_{k=1}^{\ell_r} \prod_{i=1}^k c_i^{(r)}\]
核心矛盾 增加 \(\ell_r\) → \(\tau\) 增加（好事），但 \(B\) 增大 → \(\text{SPS}(B)\) 下降（GPU 饱和，坏事）。贪心算法在两者之间找最优平衡。

7.3 贪心算法

初始所有 \(\ell_r = 0\)，\(B = R\)。每步选边际收益最大的 (request, position) 对：

边际收益分解 \[\Delta\Theta(r) = \underbrace{T(S' - S)}_{\text{全局惩罚（SPS下降影响全部已有 }\tau\text{）}} + \underbrace{a_{\ell_r+1}^{(r)} \cdot S'}_{\text{局部收益（新增 accepted prob × 新 SPS）}}\]
比较时只需比 \(a_k\) SPS 惩罚项对所有 request 相同，因此比较边际收益时只需比较 prefix survival \(a_k = \prod_{i \le k} c_i\)。\(a_k\) 最大的那个 (request, position) 被优先选中。
停止条件 当 \(\Delta\Theta \le 0\)（即 SPS 下降抵消了 \(\tau\) 增加）时停止。总复杂度 \(O(R\gamma \log(R\gamma))\)。
近最优性 \(a_k\) 单调递减 + SPS(B) 凹函数 → 边际收益递减 → 满足 submodularity，贪心解 ≥ (1-1/e)×最优。论文实测与穷举差距 < 1%。

7.4 Non-Anticipating Property 与 Lossless

截断决策 \(\ell_r\) 只依赖 drafter 输出（hidden state、采样结果、confidence），不依赖 target 的验证结果。它在 target forward 之前就已确定。

为什么保证 lossless？ \(\ell_r\) 与 rejection sampling 的随机数 \(u_k \sim \text{Uniform}(0,1)\) 统计独立。截断等价于“用更短的 block size \(\ell_r\) 做 speculative decoding”——这本身就是 lossless 的（Lesson 00 的证明对任意 block size 都成立）。
反面例子（什么会破坏 lossless） 假设 scheduler 看了 target 的验证结果后才决定截断——例如“看到 \(\tilde{x}_3\) 被拒才决定只验证到2”——这引入 selection bias，等价于只在 acceptance rate 高的 token 上采样 → 输出分布 ≠ \(p\)。DSpark 的 confidence head 避免了这个问题。

7.5 STS 校准（Sequential Temperature Scaling）

STS 校准公式 \[\hat{c}_k = \sigma\!\left(\frac{\text{logit}(c_k)}{T_k}\right), \quad T_k \text{ per-position temperature, grid search 求得}\]
为什么校准乘积而非单个 \(c_k\) Scheduler 用的是 \(a_k = \prod c_i\)，不是单个 \(c_k\)。单个 \(c_k\) 偏差小但乘积后可能累积放大。STS 逐位置调 temperature 使乘积 \(\prod \hat{c}_i\) 对齐实际 prefix survival rate（最小化 ECE）。
流程 离线验证集上收集 (predicted \(c_k\), actual acceptance) pair → 对每个 \(k\) 做 grid search \(T_k \in \{0.5, \ldots, 2.0\}\) → 存为查表。模型/数据分布变化时重新校准。

7.6 完整在线流程

每轮推理：(1) Drafter 生成 draft + confidence \(\hat{c}_{1:\gamma}\) → (2) STS 校准 → (3) Scheduler 贪心分配 \(\ell_r\) → (4) 截断后送入 target → (5) 标准 rejection sampling → 输出 accepted tokens + bonus。
