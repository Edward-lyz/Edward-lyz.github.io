# 【学习】IKP：用事实知识容量估计黑盒 LLM 参数规模

# 0. 摘要

这篇论文提出了一个很有攻击性的测量思路：不从 API 价格、吞吐、延迟、硬件成本去猜闭源 LLM 有多大，而是问它一批无法靠推理算出来的长尾事实题。模型能稳定答对越冷门、越具体、越不可推导的事实，说明它的参数里保存了越多事实关联。事实关联需要信息容量，所以事实答题能力可以反推出模型的 effective knowledge capacity，进而估计黑盒模型的有效参数规模。

论文把这种题叫做 Incompressible Knowledge Probes，简称 IKP。核心实验是 1,400 道事实题，按冷门程度分成 T1 到 T7 七档，每档 200 道；用 89 个已知参数量的 open-weight 模型做校准，再拿同一条曲线去估计闭源模型。

# 1. 基础逻辑

如果问模型 2 + 3 等于几，模型可以用规则算出来。这个题不需要模型记住某个训练样本。

如果问模型 USTC Hackergame 2023 年某个具体题目的名字，或者某个低引用 CS 研究者的研究方向和一个真实论文/系统名，模型很难用通用规则推出来。它要么见过相关文本并把关联保存进参数，要么不知道。

IKP 的基本推理链是：

```
越冷门的事实
  -> 训练语料中出现次数越少
  -> 模型越不容易学到并保存
  -> 如果模型还能答对
  -> 说明它有更大的事实存储容量
  -> 事实存储容量和总参数量有统计关系
  -> 可以用答题准确率反推 effective parameter count
```

一个 LLM 的参数可以看成它长期记忆的一部分。IKP 不问它会不会解题，而是问它记不记得世界上很多冷门但真实的事实。冷门事实越多，越需要真实容量；所以它记得越多，就越可能更大。

# 2. 主要实验结论

## 2.1 IKP 分数和参数量高度相关

论文在 89 个 open-weight 模型上拟合，声称 all-open fit 的 R² 为 0.917。模型范围是 135M 到 1.6T，跨 19 个 vendor。

Leave-one-out cross-validation 的结果是：median fold error 1.59x，68.5% 的模型落在 2x 内，87.6% 落在 3x 内。

## 2.2 MoE 看 total params，不看 active params

论文对 MoE 的观察是这样的：total params 对 IKP 的解释力明显强于 active params。

```
MoE total params:  R² = 0.79
MoE active params: R² = 0.51
```

直觉是：事实知识不只存在当前 token 激活的专家里，而是分布在全体专家权重中。虽然每次前向只用一部分专家，但训练时不同 facts 可能进入不同专家。

这对推理系统和模型规模讨论都很有影响。讨论 MoE 的知识容量时，只看 active params 会低估它的长期记忆规模。

## 2.3 thinking mode 有帮助，但不能创造知识

论文比较了 27 对 base/think 模型。thinking mode 大多提高 IKP 分数，收益集中在 T3/T4。到了 T7，收益消失。

这符合第一性原理：

> 如果事实已经在参数里，但检索路径不直接，thinking 可能帮模型找出来。
如果事实根本不在参数里，thinking 只会更有条理地不知道，或更有条理地胡编。
> 

## 2.4 Densing Law 对事实知识不成立

论文针对一个常见说法提出反驳：如果 2026 年 7B 模型能在 MMLU 上追上 2023 年 70B 模型，是不是 scaling 不重要了？

作者说，这句话混淆了两种能力。

- procedural capability 可以压缩。更好的架构、训练 recipe、data mixture 可以让小模型学会更高效的解题方法。
- factual capacity 很难压缩。某个冷门事实的具体值不见过就不知道。

论文在 96 个 open-weight 模型上控制参数量和发布日期，发现 IKP 的 time coefficient 接近 0，并拒绝 Densing Law 预测的按月提升。

我的理解：这不是说模型能力不会随时间提升，而是说同等参数规模下，长尾事实存储没有像 reasoning benchmark 那样明显变得越来越省参数。

# 3. 总结

这篇论文有意思的点在于，试图用统计学上的强相关性，证明模型的「记忆」能力，正比于模型的参数量。
